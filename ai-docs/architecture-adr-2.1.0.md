# ai-notes: ADRs of 2.1.0 (owner: architect; PLAN 2026-11-21, REFINE 2026-11-21; sub-document of ai-docs/architecture-adr.md, index in ai-docs/architecture.md; plan in ai-docs/architecture-plan-2.1.0.md)

Status: PLAN (decided by Andrea 2026-11-21 where marked). Each ADR: context, choice, alternatives, reason.

ADR-202 (2.1.0 PLAN, REFINE) LUT size and file limits. Context: the 80 MB 144-point cube is refused by the 65-point edge cap (lut.rs MAX_3D) and the 16 MiB read cap (MAX_BYTES); ffmpeg lut3d accepts 3D sizes up to 256 (MAX_LEVEL 256). Choice (Q-1 = B, Andrea): 3D edge 2..=256; 1D 2..=4096 unchanged; file read streamed up to 512 MiB (256^3 is about 450 MB); line cap 256 bytes; exactly n^3 entries; .3dl and .csp use the same rules. Alternatives: keep 65 (refuses the user's files); 144 or 160 (rejected by Andrea); unlimited (denial of service). Reason: the maintainer's maximum, bounded input. Budgets are in ADR-203, 205, 206.

ADR-203 (2.1.0 PLAN, REFINE) streaming pure parser lut/parse.rs; table u16 per channel. Context: lut.rs reads the whole file, collects tokens and formats the normalised text per entry (millions of format! calls and ~450 MB of text at 256^3). Choice: one pass over a BufRead (1 MiB buffer), keywords as today, numbers by std f32 parse on token slices, values clamped 0..=1 and quantised to u16 (x * 65535, rounded; error below one 8-bit level), table of 6 bytes per entry: 256^3 = 100.7 MB, 144^3 = 17.9 MB, 160^3 = 30.7 MB. The normalised text is produced only when a Work copy is written (ADR-206). Alternatives: f32 table (201 MB at 256; rejected for memory); a parsing crate (fast-float2 or lexical, MIT or Apache-2.0; a new dependency only by a later ADR amendment if S2 misses the budget). Reason: memory bounded by the table, no new crate. Budgets (ESTIMATE, gated after S0a/S2): parse 144^3 <= 2 s, 256^3 <= 6 s on the development machine; load peak extra memory <= table + 2 MiB.

ADR-204 (2.1.0 PLAN) path-only LUTs above 20 MB (REQ-301, Andrea's option C). Context: REQ-293 copies a LUT of 20 MB or less (normalised text) into the project. Choice: a LUT whose normalised text is above 20 MB is not copied; the project keeps its path; copy rule and 64 MiB total unchanged for the rest; a missing file uses the REQ-292 choices (Find, Export without the LUT, Cancel); no embedded fallback for path-only LUTs (copies only are embedded). Alternatives: copy above 20 MB (project grows by hundreds of MB: rejected by REQ-301); a Work-folder copy kept by the project (lost with the folder). Reason: the business rule.

ADR-205 (2.1.0 PLAN, REFINE) LutStore: src/lut/store.rs. Context: `lut::cached` parses on the calling thread (UI choose; graph build); the cache holds 8 entries without a byte budget; copies (16 entries) are unbounded in bytes; a 256 LUT takes seconds to load. Choice: states Loading(progress), Ready(Arc<Lut>), Failed(LutError), Missing, keyed by path and (size, mtime); loads run on a Background job (jobs module) that sends LoadProgress { read, total } over the existing channel; the UI tick shows the percentage in the status line; the choose returns at once; a newer choice for the same target or closing the project cancels the job (generation token checked every 1 MiB) and removes its partial Work copy; LRU by bytes, budget 192 MB of tables (one 256 table plus a 144 table, copies included); the table in use by the open project is evicted only when over budget; a file whose size or mtime changes during the read is refused ("changed while it was read"); the preview draws without the LUT while Loading and redraws at Ready (FrameKey mechanism, ADR-016); export waits for Ready on its worker and shows the progress. Alternatives: parse on the UI thread (GATE UI frame 200 ms fails); a thread per load (ADR-004 and ADR-015: threads and slots go through the scheduler). Reason: window responsiveness, bounded memory, visible progress and cancel.

ADR-206 (2.1.0 PLAN) Work folder LUT copy by content (REQ-300, REQ-301). Context: the graph writes one text file per clip (lut-clip-<i>.cube, lut-whole.cube), 80 MB at 144^3 and about 450 MB at 256^3 each; the preview rebuilds the text per graph (to_cube clone). Choice: the normalised cube is written once per distinct content and strength as `lut-<hash16>.cube` (SHA-256 prefix of the normalised text, streamed) into the private Work folder by a streamed atomic write (temp + rename, base::io), with progress; all clips, the preview and the export use the same name; the file lives until the Work folder is removed. The name is fixed by code (no user text). Golden argv of LUT projects changes (name only; the PE checks fixtures). Alternatives: pass the user path to ffmpeg (escaping, user text in a filter, file may change: rejected); symlink or hard link to the user file (cross-device, file may change); copy of raw bytes (not the validated content); keep the text in memory (450 MB at 256). Budget (ESTIMATE, gated after S4): write 256^3 <= 3 s; disk about 450 MB per distinct LUT per Work folder. Reason: filter safety, one copy on disk.

ADR-207 (2.1.0 PLAN, REFINE) applied-effects order data (REQ-304, REQ-311): Timeline.clip_order (format 12); per clip a list of movable rows top-first (Lut, Text(id), Picture(id), Subtitles); empty entries dropped; sorted by clip id (like clip_luts); rows not on the clip not stored; new rows on top; Move up and down one step each as one undo step named after the move (REQ-074). Sphere-fixed texts and sphere-fixed subtitle lines on 360 clips are fixed rows, not movable (Q-3 = A). Legacy order (format <= 11, not stored): bottom to top Lut, picture items (item order), Subtitles, flat texts (item order); later items on top, as the ASS document order gives today (verified by reading text/events.rs). Alternatives: order inside each TextItem (cannot be ordered per clip); order in view state (not saved, but REQ-311 says saved). Reason: one place per clip, same shape as clip_luts.

ADR-208 (2.1.0 PLAN, REFINE) render overlay stage (REQ-305, REQ-304). Context: today the LUT is in the clip chain before the frame composition and fades; texts, subtitle lines and picture items are drawn after the concat, so a text is never graded by a LUT. Choice: a clip whose stored order differs from the legacy order is built by render/overlay.rs: fixed chain (crop, scale, move, frame composition, fades), then movable rows bottom to top, one filter step each: Lut (lut3d tetrahedral on the Work copy), Text and Subtitles (subtitles= on `ov-<clip>.ass`, clip-local times, that row's events only), Picture (overlay with enable). Clips with the legacy order keep the legacy graph (argv identical). Preview and export use the same builder. Alternatives: always the overlay stage (golden argv of all projects changes); one global ASS with a LUT per segment (cannot grade only some clips' texts without splitting the timeline). Reason: exact per-clip order with unchanged old projects. 360 scope: sphere-fixed items keep their 2.0.4 path (Q-3 = A).

ADR-209 (2.1.0 PLAN, REFINE) LUT placement in new projects (Q-2 = A, decided by Andrea): the LUT of an overlay-stage clip is applied after the frame composition (background and bars graded) and after the fades. Consequences: a LUT that lifts black shows on a faded frame (ASSUMPTION); the frame background is graded. Alternatives: LUT inside the picture chain before the frame (cannot be placed above the texts). Reason: the widget order is the render order; the user chose the whole frame.

ADR-210 (2.1.0 PLAN) format 12 (REQ-311): SCHEMA_VERSION 12, loads 1..=12, always written as 12; 2.0.4 refuses 12 (TooNew, file untouched). Additive fields with serde defaults: Timeline.clip_order; TextItem.shadow (px at 1080, colour; default 0 px, black); subtitle style fields (shadow px and colour, highlighted and not-yet colours, enlarge px default 12); Preset variants EnlargeWord and Typewriter. Load: damaged order entries dropped with a notice line in the "Some files could not be found or were repaired" list; out-of-range shadow or enlarge values set to defaults with the same notice. Alternatives: no bump (2.0.4 would open 2.1.0 files and lose the order: rejected); a bump per stage (rejected, D58 rule). [TECHNICAL, one bump rule of ADR-169]

ADR-211 (2.1.0 PLAN, REFINE) shadows (REQ-306, REQ-307 kept as written). REQ-307 requires the ASS export to write the shadow distance as the style's Shadow and the colour as its BackColour. Context: in libass BorderStyle 3 (box) the box and its shadow take colours from the style; the 2.0.4 Boxed preset and TextBox style put the box colour in both OutlineColour and BackColour (&H80000000). Design A (primary; to verify in spike S0d): BackColour = shadow colour and Shadow = px * H / 1080 for every style, boxes included; the box fill moves to OutlineColour if libass draws the box fill from OutlineColour (look unchanged, both were &H80000000). Design B (fallback, if S0d shows the box fill comes from BackColour): the style keeps Shadow and BackColour as REQ-307 says, and the box is drawn as a vector rectangle event (\p1) in the box colour, placed behind the text and after the shadow, sized from the in-house measure; risk: geometry must match the 2.0.4 box at 1080 px. Shadow 0 writes the 2.0.4 style values (no output change). Styles: one per distinct (box, shadow colour, box colour) for text items; one project style for subtitles. Rejected: copy events for boxes (would make the ASS file differ from REQ-307 wording); libass \xshad/\yshad (box shadow behaviour not verified). The PE records the S0d result and the chosen design in ai-docs/code notes; the architect amends this ADR if design B is needed.

ADR-212 (2.1.0 PLAN) subtitle colours (REQ-308): Highlighted = PrimaryColour, Not yet highlighted = SecondaryColour of the WordHighlight style (existing \k mapping; project colours; defaults white and yellow); the ASS export carries both. [TECHNICAL]

ADR-213 (2.1.0 PLAN) Typewriter and Enlarge word (REQ-309, REQ-310) in src/word_styles.rs (pure plans; ass.rs writes). Typewriter: one event per word; spoken words in the Not-yet colour (inline \1c), future words hidden (\alpha&HFF&), the current word with \k letter tags over a transparent Secondary, so letters switch to Highlighted at their times; words under 0.1 s appear at once. Enlarge: a base line event per word time with the active word hidden (\alpha&HFF&, layout kept) plus one event for the enlarged word at its measured centre (\fs = size + N, \pos from the in-house layout). Alternatives: \fscx scaling (other words move); per-letter events (event count up to letters per line; cap 20000 at risk); karaoke \kf (a fade, not a reveal). Risk: Enlarge centre accuracy (S0b). [TECHNICAL]
