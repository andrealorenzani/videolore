# ADR 2.3.0 (PLAN 2026-11-22, REFINE same day; ADR-230..243; status PLANNED unless marked; ADR-242 and ADR-243 decided by Andrea)

ADR-230 (2.3.0, PLAN) project format 14 (one bump, D-format): `Clip.overlaps`, `Timeline.next_overlap_id`; `Clip.crop` not written. Context: overlaps need stored data bound to a clip; crops are removed (REQ-283). Choice: 14 written always; 15+ refused by 14 (existing TooNew rule, REQ-029); 1..=14 read; 13 converted in memory once (ADR-241). Alternatives: a separate overlay list in the project (rejected: split, trim and delete would need a second rule set); a new file version per feature (rejected: one bump per development). Reason: one place for everything a clip owns.

ADR-231 (2.3.0, PLAN; speed rule decided by Andrea Q-B, 2026-11-22: Change speed rescales the clip's overlap times with the speed) overlap model in pure `src/overlap.rs`. Choice: `Overlap{id, path, kind Still|Motion, from, len, place, width, height, reshaped}`; `from` is an offset from the clip's timeline start, so ripple moves it; functions clamp, cut to a kept part, split, list the removals of an edit, rescale for speed. Alternatives: absolute timeline times (rejected: ripple would need to move each overlap; drift on trims). Reason: the clip is the owner (REQ-329 rules come out of the clip edits).

ADR-232 (2.3.0, PLAN) render: three paths. (1) legacy argv (default order): overlaps as picture-like overlays after the concat (`plan.rs picture_overlays` generalised), no change for projects without overlaps; (2) step builder (`render/steps.rs`): overlap row as `Step::Over(n)`; (3) preview: same plan. Motion overlays (GIF, MOV) play once: no loop, `setpts` from the start, `overlay=eof_action=pass` without `shortest`, so after the animation the overlay is transparent (REQ-328). Still (PNG): `-loop 1` as picture items. Box: default fit inside the box (box kept at the media ratio); reshaped MOV Cover (`increase` then `crop`), reshaped GIF or PNG Stretch (REQ-327). Alternatives: draw overlaps only in the step builder (rejected: every clip with an overlap would leave the legacy argv; the legacy path is proven); a second ffmpeg process per overlay (rejected: no). Reason: reuse the picture path, which is tested and gated.

ADR-233 (2.3.0, PLAN; preview size amended by ADR-243) alpha: software decoding for every overlay input; hardware decoding (preview only) skips overlay files. Size: PNG header (`parse_png_size`), GIF header (new `gif_size`, bounded 13 bytes), MOV ffprobe; 16 Mpx refusal at add and again at use (REQ-316). Alternatives: hardware decoding with an alpha check (rejected: no reliable check per GPU); copy the picture into the project (rejected: not requested, REQ-287 keeps the path). Reason: correct picture first; the preview cost is Q-C. Codecs: qtrle and ProRes 4444 are assumed to carry alpha (fixtures in the PE stage).

ADR-234 (2.3.0, PLAN) removal warning (REQ-329): the dispatcher computes `overlap::removals(edit)` before changing anything; a non-empty list opens one popup (count, OK, Cancel) that holds the pending command; OK applies command and removal in one history step; Cancel changes nothing. Alternatives: remove silently with undo (rejected by Andrea's Q7 answer: a warning); block the edit (rejected: Q7 option a/b). Reason: one popup per edit, the user decides once.

ADR-235 (2.3.0, PLAN; BUG FIX, business REQ-333 as the fix of REQ-309) Enlarge word: the enlarged word is its own event at its measured place. Cause: the word grows inside the line with `\an5` and `\pos` of the line, so the line's width and box change and the word moves (word_styles.rs:111-147; ass.rs line_tag). Choice: base event unchanged; enlarged event `{\an5\pos(cx,cy)\fs<big>}word` with cx from measured line and word widths (measure.rs, the text-fit shaping; harfrust and skrifa already direct dependencies), cy from ascent and descent so the baseline stays. Alternatives: `\fscx`/`\fscy` only (rejected: grows from the left edge, not the centre REQ-309 promises); keep the in-line run and add a placeholder (rejected: same line-box problem). Reason: REQ-309 acceptance (centre kept, others still) with the existing measure code. Fallback if the 2% acceptance fails: the `\fscx` form with a measured `\pos` shift (decided after the PE measurement).

ADR-236 (2.3.0, PLAN) Change aspect per clip (REQ-326): no storage change; UI only. The clip row offers Off, the three shapes, Fit (width or height) and Empty space (colour, or blur with Low, Medium, High). A first shape choice uses `FrameAspect::default()` (Fit on width, black); an existing own aspect keeps fit, fill and blur. Alternative: store a separate per-clip fit (rejected: `FrameAspect` already has it). Reason: the gap is in ui/popups.rs:689 (forced Fit::Height); the whole-video popup is checked by the PE.

ADR-237 (2.3.0, PLAN) Volume and Change speed as effects: storage unchanged (`Timeline.clip_volume`, `Clip.speed`); Volume popup uses the REQ-129 keyframe timeline; the slider stays, disabled with the note while keys exist (TECHNICAL, follows REQ-280); Change speed applied to one clip or to all (one copy each, REQ-147 copy rule; new use for a non-keyed effect; R7). Alternative: keep the Clip details rows (rejected by Andrea's Q3 and Q5 answers). Reason: effects are the one place to add and remove effects.

ADR-238 (2.3.0, PLAN) Crop removed (REQ-283, Q4): `Step::Crop`, `crop_filter` use, `Row::Crop`, the Crop row, the Crop % row and the writer of `Clip.crop` go; 13 crops are dropped with the count in the one status line (REQ-332). Alternatives: keep as built (Q4 a, rejected by Andrea), keep the data and hide the control (Q4 c, rejected). Reason: the manual cut overlapped with Fit; the removal makes the order simpler (no crop pair rules).

ADR-239 (2.3.0, PLAN) Add media (REQ-324, MINOR): the Media button calls the import action (File > Import media…); one command, two places. Alternative: a new command (rejected: duplicate). Reason: the same rule as the menu.

ADR-240 (2.3.0, PLAN) Never removed (REQ-295, Q9): `SplashOption` keeps Always and OncePerVersion; `lenient_splash` maps the string "Never" to OncePerVersion explicitly; the settings file stays version 2. Trap noted: the current lenient parser would turn an unknown "Never" into the default (Always) once the variant is removed. Alternative: keep a hidden variant (rejected by Q9 option c; more states to test).

ADR-241 (2.3.0, PLAN) 13 to 14 conversion and order rows: `src/project/v13.rs` converts in memory at load: crop dropped (count); picture items under a clip's start become overlaps of that clip (same times, place and box), their order rows `picture:<id>` become `overlap:<new id>` on that clip; damaged order entries repaired with the 2.1.0 line; one status line. Rows: `Row::Overlap(u64)` named `overlap:<id>` in the picture group, on top by default (MINOR); `crop` read as Unknown and dropped. No undo step, no change mark. Alternative: convert on save (rejected: a file opened and not saved would keep the old picture items, two states). Reason: the same pattern as the 1.6.1 format 9 conversion (`project/v9.rs`).

ADR-242 (2.3.0, DECIDED by Andrea, Q-A, 2026-11-22) timeline lane for overlaps: one shared overlap lane for the whole timeline (`ui/overlap_lane.rs`); overlapping overlaps are stacked in sub-rows (pure layout function: greedy by start time); at most 3 sub-rows visible, the rest reached by vertical scroll inside the lane; each overlap shows its two ends, dragged on the lane (clamped to its clip). Alternatives (rejected by Andrea): one lane per clip under the clip; a lane only for the selected clip; no lane with ends in a popup. Reason: the closest reading of REQ-325 "its own lane" with one place for all overlaps; the 3-row cap keeps the timeline height bounded.

ADR-243 (2.3.0, DECIDED by Andrea, Q-C, 2026-11-22) preview size of large overlay files: an overlay file whose frame is larger than 1920 x 1080 (PNG, GIF or video) is drawn at half its box size in the preview graph only; the export draws it at full size. Files of 1920 x 1080 or less are drawn at their size in both. Software decoding stays for all overlay files (ADR-233); the 16 megapixel limit (REQ-316) is unchanged. Alternatives (rejected by Andrea): full-size preview with no change (may drop frames on 4K ProRes); refusing MOV above 1920 x 1080 (new product limit); hardware decoding of overlays (wrong picture where alpha is dropped). Consequence: the preview and the export differ in detail for such files; REQ-325 and REQ-331 wording amended by the PM. Reason: keeps the preview responsive with the software decoder; the export keeps full quality.
