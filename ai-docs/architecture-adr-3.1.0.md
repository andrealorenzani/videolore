# ADR 3.1.0 (PLAN 2026-11-24; ADR-244..254; status PLANNED unless marked)

Format as ai-docs/architecture-adr.md. Requirements: REQ-334..340 (docs/business*.md). Open questions: none [SEVERE]; the [SEVERE] Q-F1 (ADR-244) is answered by Andrea (2026-11-24); the rest [TECHNICAL], decided here.

ADR-244 (3.1.0, PLAN; DECIDED by Andrea, answer to Q-F1 (a) 2026-11-24: always write format 15 for every save) project format 15, one bump for the development. Stored: `Clip.audio_track` (ADR-245), `MediaFormat.audio_tracks` (ADR-245), subtitle style `Preset::AsTrack` (ADR-249). Reader 1..=15; writer always 15 on every save (as ADR-230); 16+ refused by 15 (TooNew, REQ-029). Format 14 opens with the new fields at their defaults: no conversion module; `v14_tests.rs` keeps its tests. Context: REQ-029 refuses newer files; the PM note asks for a new number. Choice: every save writes 15. Alternative rejected by Andrea: write 14 unless a 3.1.0 setting is used (would keep 3.0.x able to open projects that do not use the new features; needs a writer rule and a second golden set). Reason: one rule as in 2.3.0 and 2.2.0; fewer branches; the consequence is accepted. Consequence: 3.0.x cannot open any project saved by 3.1.0 or later (refused with the TooNew message, never modified); release note line "projects saved by 3.1.0 open only in 3.1.0 or later".

ADR-245 (3.1.0, PLAN) audio track model. Choice: a track is its ordinal among the file's audio streams (`-map 0:a:<k>`, k = 0..31), as `SubtitleTrack.ordinal` does. `MediaFormat.audio_tracks: Option<Vec<AudioTrack{ordinal: u8, language: Option<String>, title: Option<String>, channels: u32}>>`, `None` = not analysed (REQ-186 re-probe, as `subtitle_tracks`), `Some(empty)` = no audio. Titles sanitised and ≤ 64 characters (as the subtitle tracks), languages through `valid_language`. `Clip.audio_track: u8` (serde default 0, not written when 0). Validation on load: k ≥ count (or analysis missing and k > 0) → 0, one status line ("N clip track choices reset"). Alternatives: stream index (rejected: `a:k` is what ffmpeg filters take and is stable); language (rejected: two tracks may share one); per-track map in `Timeline` (rejected: split, trim and merge would need a second rule set; ADR-230 reason). Reason: the clip owns its settings.

ADR-246 (3.1.0, PLAN) export of a non-first track. Choice: a clip with `audio_track != 0` is an effect for the tier rule of ADR-006: T1 (stream copy) is refused, the re-encode path (T2) maps `[n:a:k]` in the graph. Track 0 keeps today's argv (golden tests unchanged). Alternatives: `-map 0:a:k -c copy` in T1 (rejected for 3.1.0: changes T1 argv for one case and needs the stream-copy checks of ADR-017 to be rewritten; future work). Reason: smaller change, the rule "no effect, no stream copy" stays true. Cost: export time of such clips is a re-encode (NFR, risks).

ADR-247 (3.1.0, PLAN) preview audio and proxies. Choice: the preview graph reads `[n:a:k]` of the clip's effective input (ADR-016). A proxy (ADR-018) keeps every audio stream in order (`-map 0:a?` instead of `0:a:0?`), so ordinal k matches. The proxy cache key gets a layout number (bump) so old proxies (track 0 only) are rebuilt once. The frame key (FrameKey) and the audio restart include the track, so a change restarts audio. Alternatives: audio always from the original file (rejected: a second input per clip in every preview graph and a second decoder). Reason: one input per clip stays. Proxy size: one 128k AAC stream per track (accepted, NFR).

ADR-248 (3.1.0, PLAN; replaces the placement rule of ADR-235 for REQ-334; REQ-333 replaced) Enlarge word from its base. Context: REQ-334 keeps the baseline and grows the word upwards; the words before shift left and after shift right by half the extra width. Choice: a pure module `src/word_layout.rs` (imports base only) takes the measured word widths of a line (from `measure.rs`, unchanged) and the enlarged index and extra width N, and returns each word's left x and the baseline; the enlarged word is its own event anchored bottom-left at (left, baseline + descent) with the enlarged size; the others are events at their x. Only a line with an enlarged word uses per-word events; other lines keep the 2.3.0 events. The line box grows upwards (MINOR, PM). Alternatives: `\fscx`/`\fscy` (rejected: scales the strokes; ADR-235); keep the 2.3.0 centre rule (rejected by Andrea in REQ-334). Reason: the rule is a pure function, tested without ffmpeg. Consequence: old projects with Enlarge word change look on opening (release note, PM R10).

ADR-249 (3.1.0, PLAN) "As subtitle track" style (REQ-337). Choice: `Preset::AsTrack` (serde `as_track`, label "As subtitle track"). Export: no ASS burn-in of lines (the `Ass` step for lines is not built); the existing separate track writer (`render/plan.rs` track block: `srt::write` with `mov_text` for MP4 and MOV, SRT for MKV) writes the track; the Subtitles choice of the export dialog is fixed to `SubtitleMode::Separate` (runtime, not stored). Preview: lines drawn with the Classic look (ASS, editor only; assumption A-3.1-1). Track text and times only (MINOR, PM). A 360 export uses the same track writer. Alternatives: a second ASS track with styling (rejected: players draw it differently; ASS rule of REQ-307); a sidecar .srt file (rejected: REQ-182 asks for a track in the file). Reason: reuse of the 2.0.x track writer.

ADR-250 (3.1.0, PLAN) blurred fill fix (REQ-335). Defect: as reported on 2.3.0, a clip's Change aspect with Fit on width and the blurred fill shows no fill. Choice: one path for the whole video and a clip: the background of a clip frame is built from the same `blur_chain` when the fill is Blur; the PE finds where the clip's aspect is dropped (candidates to check first: `render/steps.rs` `frame_row` gating of `blur`, and the clip aspect carried in `SegFrame` in `render/graph.rs` `compose_frame`; the UI popup `ui/popups.rs` clip_aspect_rows keeps fit and fill). No storage change. Tests: string test of the graph (blur chain present for the clip row), pixel test with the pinned ffmpeg (bands blurred, middle sharp, preview and export within 2 %). Alternative: a fallback colour (rejected: not what REQ-335 asks).

ADR-251 (3.1.0, PLAN) Overlap media Effects row (REQ-336). UI only: the Effects list gets a row for Overlap media after Add Text (`ui/effects.rs` row list, same row drawing as Scale). `effect_order::Row` and storage unchanged. Alternative: keep the shared row (rejected by the Andrea request).

ADR-252 (3.1.0, PLAN) player Audio menu (REQ-338). Choice: the player's in-memory one-clip project sets `Clip.audio_track` (ADR-245) from the menu; the same preview path plays it (ADR-247); nothing is saved (REQ-252 unchanged); the choice is kept while the same file is open in the session (REQ-251). Track list from the probe of the file (ADR-245). No network code added (the player's `cargo tree` check stays). Alternative: a second audio pipeline in the player (rejected: parity with the editor and a second place for the sound).

ADR-253 (3.1.0, PLAN) Subtitles effect audio track (REQ-339). Choice: the popup's Audio track is an argument of the Subtitles command, not stored: the lines are the result and carry the undo step. Recognition extraction (`stt.rs` `-map 0:a:0`) takes the chosen `k`; the word timing matches the chosen track (REQ-095); the subtitle track text (Use) is unchanged (REQ-087). Alternative: store the choice on the clip (rejected for 3.1.0: nothing reads it later; future work if asked). Reason: no new stored state.

ADR-254 (3.1.0, PLAN) Volume and track (REQ-340). Choice: the Volume popup gets the Audio track choice (list from `audio_tracks`), stored in `Clip.audio_track` (ADR-245); the keyed volume (REQ-280) applies to that track; Merge (REQ-008) compares the track with the volume; the 360 spatial pre-pass (`spatial.rs` `0:a:0`) reads the clip's track and its cache key includes it. Alternative: the track in the `ClipVolume` record (rejected: the track exists without any volume key). Reason: one clip field read by preview, export, player and merge.

Cross-cutting rules for 3.1.0 (TECHNICAL): every cache keyed by a media file that reads audio (pre-pass, proxy, FrameKey, STT extraction work folder) includes the track ordinal. The track number is a number in argv; no string from a project reaches argv (ADR-002 rules). Tests keep `VIDEOLORE_REQUIRE_FFMPEG` behaviour.
