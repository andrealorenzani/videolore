# ADR 3.1.2 (built 3.1.2, 2026-11-26; ADR-255..270)

Format as ai-docs/architecture-adr.md. Requirements: REQ-341..352, 355..358 (docs/business*.md). Andrea's decisions (REFINE 2026-11-26): Q-A WAV kept, recorded into MKV (ADR-262); Q-B Linux X11 and XWayland only, a native Wayland session gets a message before Start (REQ-358, ADR-265); Q-C computer sound needs macOS 14.6 or later, older Macs get a message at Start; installer minimum of the recorder 11.0 (ADR-269). "Built" lines state the code as shipped; "Deviation" lines state what differs from the plan (sources: ai-docs/code.md, docs/code-screen-spy.md). Plan: ai-docs/architecture-plan-3.1.2.md (archived at release).

ADR-255 (built) third program. Choice: workspace member `screen-spy/`, package and binary `videolore-screen-spy`, library plus thin `main.rs`. Built: depends on `videolore` with `default-features = false` and **no features** (no `audio`, no `stt`, no `ureq`, no `whisper-rs`, no `rustls`; CI `cargo tree` check). Deviation: the plan's `features = ["audio"]` was dropped; cpal is the recorder's own dependency on Windows and macOS only (`[target.'cfg(any(windows, target_os = "macos"))'.dependencies]`). Alternatives: a mode of the editor or the player (rejected: REQ-341 needs its own installers); a separate repository (rejected: shared ffmpeg pin, notices, CI and version script). Reason: the player's pattern is built and tested.

ADR-256 (built) video capture by ffmpeg input devices. Choice: one ffmpeg child per state: `gdigrab` on Windows (`-offset_x`, `-offset_y`, `-video_size`, `-i desktop`), `avfoundation` on macOS, `x11grab` on Linux (`-i :<DISPLAY>+X,Y`). Video scaled with `scale` and `pad` (aspect kept, black bars), frame rate from the format. Deviation: the macOS input is the screen **name** `Capture screen N` (not the index of ADR-258; see ADR-258). Alternatives: in-process capture (xcap 0.9.10, scap 0.1.0-beta.1) with raw frames piped to ffmpeg (rejected: raw 4K30 NV12 about 370 MB/s through a pipe; scap pre-release without audio; xcap pulls libpipewire at build time on Linux); pinray 0.2.4 (rejected: minor versions may break the API). Reason: the bundled ffmpeg captures on the three systems, one encoder path.

ADR-257 (built) preview. Choice: the same ffmpeg child has a second output: `split` into the recording output and a preview output (`fps=5`, `scale=640:-2`, `rawvideo rgb24` on stdout), read by a thread that keeps only the newest frame (`preview::Feed`). Before Start a preview-only child runs (`-nostdin`); Start stops it and starts the recording child (about 1 s without picture). Deviation: a preview-only child also runs between recordings. Alternatives: a second capture child during recording (rejected: double cost); preview from the file (rejected: REQ-343, the preview is not part of the file).

ADR-258 (built) screen list and geometry. Choice: crate `display-info` 0.5.10 (Apache-2.0). Screens numbered in the order the crate returns them, labelled "Screen N, WxH" (REQ-344). Units: Linux divided by the Xft scale, macOS points, Windows pixels (`screens::physical`). Deviation: avfoundation takes the device **name** `Capture screen N` (plain numbers count the cameras first, so the ADR-258 index was wrong); the list is read every 2 s; a removed recorded screen stops the recording with that cause. Consequence: display-info adds xcb and smithay-client-toolkit to the Linux build (libxcb-randr development files: `libxcb-randr0-dev` on CI and the dev box). Alternatives: xcap (rejected, ADR-256); own Win32 or CoreGraphics code (more unsafe code).

ADR-259 (built; Q-C decided) sound. Choice: Linux: ffmpeg `-f pulse` inputs, `@DEFAULT_MONITOR@` for computer sound and `@DEFAULT_SOURCE@` for the microphone; each tried for 0.1 s before Start; when ffmpeg lists only monitors there is no microphone; when the **default source is a monitor** Start is refused with a message (it would record the computer's sound twice); no source name is passed to ffmpeg. Windows: cpal 0.18.2 WASAPI loopback of the default output (computer sound) and cpal default input (microphone). macOS 14.6 or later: the program's own CoreAudio tap (`macos::SystemTap`, `initStereoGlobalTapButExcludeProcesses`, inside a private device) recorded by cpal as an ordinary input. Deviation: the plan's cpal CoreAudio loopback was not used, because cpal's loopback records the inputs of an output device that has some; the cost is more `unsafe` (ADR-264). Older macOS: Start refused with a message naming macOS 14.6 (REQ-357); the tap is never created below 14.6. Launch safety (A-3.1.2-13): the CoreAudio symbols are linked **weakly** through `.cargo/config.toml` (`rustflags = ["-C", "link-arg=-Wl,-weak_framework,CoreAudio"]`, all of CoreAudio), not through `dlsym`; CI checks the built programs with `nm -m` that the process-tap symbols (`_AudioHardware(Create|Destroy)ProcessTap`) are weak imports. Each source writes 16-bit stereo PCM over TCP (ADR-260); ffmpeg reads `-f s16le -ar <rate> -ac 2`, `amix` (`normalize=0`) and `alimiter`; silence filler by the wall clock when a source is more than 200 ms behind. Microphone permission asked before anything opens, answer awaited up to 2 minutes (`microphone_gate`). Alternatives: ffmpeg `wasapi` input (does not exist; ticket #9408 open); DirectShow with a virtual cable or BlackHole (third-party drivers, rejected by REQ-357); ScreenCaptureKit audio (macOS 13 and later; rejected by Q-C (a)); Rust encoders (none mature).

ADR-260 (built) audio transport. Choice: the recorder listens on `127.0.0.1` on an ephemeral port per cpal source and ffmpeg connects to `tcp://127.0.0.1:<port>`; the listener accepts only a 127.0.0.1 peer and one connection per source; PCM is never written to disk. Built: `audio::Feeder`; audio is always stereo (deviation: the plan did not fix the channel count). Accepted risk: another process of the same user can connect to the port while recording (same trust as the user's own files). Alternatives: a named pipe (needs libc or new crate with unsafe calls; Windows behaviour unverified); a temporary file (not live); ffmpeg stdin (taken by the stop command and the video path).

ADR-261 (built) output file and stop. Choice: MP4 (AAC or MP3) written fragmented (`-movflags frag_keyframe+empty_moov+default_base_moof`); WAV written as Matroska (`-cluster_time_limit 1000`). A file cut short by a crash, a full disk or a removed screen keeps the written part and plays (REQ-350; a killed recording keeps all but about the last second). The file is written straight to the chosen path; ffmpeg `-y` only after the Replace confirmation (`-n` otherwise, REQ-346). Stop writes `q` and a newline to the recording child's stdin; wait at most 15 s (`process::STOP_TIMEOUT`), then the child is killed. The recording child is the only ffmpeg started without `-nostdin` (ADR-002 exception). Alternatives: temporary name and rename (a crash leaves a hidden file); plain MP4 (unplayable after a kill); a signal (Windows has no signal for a console child).

ADR-262 (built; Q-A decided) codecs and containers. Choice: video `libx264 -preset veryfast -crf 23 -pix_fmt yuv420p` with a key frame every second; audio AAC (native `aac`, 160 kbit/s) or MP3 (`libmp3lame`, 160 kbit/s) into MP4; WAV (`pcm_s16le`) into MKV. Container follows the audio format (REQ-348, REQ-345, REQ-347); no pair refused. Consequence: a WAV recording is a `.mkv` file (stated in the Output text and the release notes). Alternatives: hardware encoders (later: CPU cost of 4K30 and 1080p60 is the risk, not measured); libx265 (more CPU, less compatible). Reason: H.264 in MP4 plays in every target player; PCM cannot go into MP4.

ADR-263 (built) settings and default folder. Choice: `screen-spy.json`, version 1, in the recorder's configuration folder (directories; regular file, 64 KiB cap, defaults on damage with the damaged file kept as `.bad`, atomic write); keys: folder, video format, audio format (REQ-352). Default folder: `directories::UserDirs::video_dir()` (Videos on Windows and Linux, Movies on macOS); home folder when none exists. Alternatives: a settings file shared with the editor (rejected: a different program with its own schema). Reason: the file is never next to a recording.

ADR-264 (built) permissions, platform checks and missing sources. Choice: before Start the recorder checks, on the window thread (quick, macOS asks there): machine blocked (native Wayland, ADR-265; no display; macOS below 14.6), file name and folder, "Replace the file?", the chosen screen still there, the macOS screen recording permission. Then on a thread of their own (`Phase::Starting`, polled by `tick`): ffmpeg devices and encoders (ADR-266; kept after a successful start), then the sources (microphone, computer sound; each opened once). Deviation from the plan's order (ADR-264 first version: Linux session, devices, macOS version, screen, permission, sources): screen and permission come before the devices, as the user asked; the macOS version is checked with the session. Permission: `CGPreflightScreenCaptureAccess() || CGRequestScreenCaptureAccess()` (objc2-core-graphics, safe bindings, no unsafe block); the request shows macOS's prompt once and the message says that macOS applies it after the program restarts. Cancel start: the button reads **Cancel start**, the result of a cancelled start is discarded (an opened sound is closed), closing the window quits at once. Alternatives: no preflight (rejected: black picture and no message).

ADR-265 (built; REFINE B, Andrea) Linux sessions. Choice: X11 sessions and XWayland (`DISPLAY` set, no native Wayland session) only. A native Wayland session is detected when `WAYLAND_DISPLAY` is set or `XDG_SESSION_TYPE` is `wayland`; then the recorder shows, before Start, the REQ-358 message, no file is created and the button still reads Start recording. On XWayland only X clients are captured. Alternatives (not chosen by Andrea): xdg-desktop-portal ScreenCast with PipeWire (ashpd, pipewire; later version); no Linux recording (rejected). Reason: no ffmpeg input exists for PipeWire screencasts.

ADR-266 (built) ffmpeg checks. Choice: the recorder finds ffmpeg with the editor's lookup (`videolore::ffmpeg::locate`, ADR-013: settings override, environment, bundled directory next to the executable, PATH last) and runs `ffmpeg -hide_banner -devices`, `-sources pulse` (Linux) and `-encoders` on the start thread (`devices.rs` readers, the result kept after a successful start); a missing device or encoder names it in the message. Packaging smoke test (`scripts/package.sh`, docs/code-packaging.md) requires `x11grab`, `pulse`, `gdigrab`, `avfoundation`, `aac`, `pcm_s16le` in the bundled build. Reason: REQ-350 names the cause.

ADR-267 (built; amends 254; REQ-355, 356) player playlist. Choice: File > Open… uses `rfd` `pick_files()` (as the editor, `src/dialogs.rs`) and replaces the list (`Playlist::replace`: each once, at most 10 000 entries, projects left out) and plays the first video. File > Add to playlist uses `pick_files()` too and appends in the chosen order without stopping the current video; title `name (n of m) — videolore player` when the list has more than one video (`Playlist::place`). Commands: `OpenVideos(Vec<PathBuf>)`, `AddToPlaylistPaths(Vec<PathBuf>)`. After the last video has ended, an added video does not start playback by itself (assumption A-3.1.2-12, as documented). Deviation: a video opened by itself (drop, command line) heads the list it starts. Alternatives: a command per file (rejected); keep duplicates (rejected: 2.0.4 rule stays).

ADR-268 (built) test and coverage strategy for platform code. Choice: platform, environment and macOS version are injected values in the pure builders (`plan.rs`, `session.rs`, `devices.rs`, `screens.rs` numbering, `audio.rs` padding and conversion), tested on the Linux CI runner. The `cfg`-gated adapters (cpal, display-info, CoreGraphics, CoreAudio tap, AVFoundation calls) are thin and checked by hand (business verification items 38 and 39). Real capture test: `tests/ffmpeg.rs` `the_recorder_records_a_real_x11_screen_with_pulseaudio_sound` under Xvfb with a private PulseAudio server, `VIDEOLORE_REQUIRE_CAPTURE=1` (CI step; never a desktop's sound server); covers MP4 and MKV. Test counts at build (ai-docs/code.md): 48 unit and 5 integration tests of the recorder. Alternatives: no real test (rejected); a fake ffmpeg script (rejected: the bundled build is what ships).

ADR-269 (built) packaging and CI. Choice: the recorder is a product of `scripts/package.sh` like the player (`screen-spy`), identifier `io.github.andrealorenzani.videolore-screen-spy`, own notices `rust-crates-screen-spy.txt` and `third-party-screen-spy.txt`, `packaging/linux/screen-spy.desktop` for the AppImage (no desktop integration written by the program), no file association, the default NSIS template, macOS `packaging/macos/screen-spy-info.plist` (microphone and system-audio usage texts, `info-plist-path`), macOS minimum system version 11.0 as the editor and the player (NOT 14.6: older Macs must open it to show the message). CI: the executables job names it, the package matrix calls it, `installer-config.yml` checks its packager files, the network check covers it, `version.sh` lists `screen-spy/Cargo.toml`, `feature-coverage.sh` searches `screen-spy`. Each installer bundles its own pinned ffmpeg (REQ-040): about 70 to 130 MB (estimate, not measured). Alternatives: shared runtime or ffmpeg download at first start (rejected: REQ-040, no-network rule).

ADR-270 (built) icon, splash and About. Choice: the recorder uses the editor's icon files (as the player); no start splash (REQ-133 is the editor's, REQ-154 the player's); About lists the recorder's components through `videolore::notices` with its own crate list (REQ-342).

Cross-cutting rules (built, TECHNICAL): the recorder spawns ffmpeg only in `screen-spy/src/process.rs`; at most one ffmpeg child at a time; every argument is a number, a closed list, the user's folder and file name, or the screen geometry (no text from a file or the system reaches argv); `file`, `pipe` and `tcp` protocols only; no network code; no call into a macOS 14.6 API below 14.6; `#![deny(unsafe_code)]` in the recorder's `lib.rs`, allowed only in `macos.rs` (`#[allow(unsafe_code)]` on the module; about seven SAFETY-commented sites: AVFoundation microphone status and request, CoreAudio tap and private device, identifier release). Deviation: the plan's "at most one reviewed site" became one reviewed file.

Open checks at build (ASSUMPTIONS not verified on hardware): A-3.1.2-3 (avfoundation screen name order vs display-info order), A-3.1.2-11 (Info.plist keys), A-3.1.2-13 (launch on macOS 11 to 14.5), gdigrab offsets, DPI, Windows loopback, macOS tap permission behaviour; see docs/architecture-screen-spy.md#not-verified.
