# ai-notes: ADR for 3.2.0 (PLAN 2026-11-28; planned, not built; owner: architect)

Format of each record: id, status, choice, alternatives, reason. Ids continue ADR-275 (3.1.3).

ADR-276 (planned) ruler marks and pointer line. Choice: pure function `ui::ruler::marks(t0, t1, zoom, fps) -> (Vec<f64>, Step)` in src/ui/ruler.rs. Steps in seconds: 1/fps (frame), 1, 60, 600, 3600. The step is the smallest one whose spacing is at least MARK_GAP = 6 px at `zoom` px/s. Labels keep the REQ-093 table (`ticks`, STEPS) and `LABEL_GAP`; labels are drawn only at label ticks that also fit. Pointer line: an overlay painted after the clips in src/ui/timeline.rs at the pointer x, from the ruler top to the clip bottom, only while the pointer is inside the timeline rectangle; time = the same x-to-time mapping a click uses (no new mapping). Alternatives: one table of all steps shared with labels (rejected: labels would show frames at low zoom); line only in the ruler (rejected by REQ-368). Reason: one rule per concern, pure and testable at three zooms.

ADR-277 (planned) picture strips. Choice: new module src/strips.rs (pure planner, LRU cache, job submission). Lower half of each clip (from its mid height to bottom): thumbnails at grid times clip start + k * step, step = the smallest value of the ruler STEPS table (1, 2, 5, ... s) whose spacing at zoom fits the thumbnail width + 4 px. Source time of thumbnail k = in-point + k * step * speed (clip speed, 50 to 200 %). Decoding: one ffmpeg child per (media, in-point, step) request: `-protocol_whitelist file,pipe -ss <in> -i <file> -vf fps=1/<step>,scale=<w>:<h> -frames:v <n> -f rawvideo -pix_fmt rgba pipe:1`, input = the preview copy when the media has one (REQ-038), else the source; run in `Priority::Background` (the lowest; jobs.rs), at most one strip job at a time, cancelled when the clip, zoom or setting changes. Cache: in memory only (no file on disk), LRU keyed by (media, source time rounded to the step), cap 32 MiB of RGBA. Thumbnail box: height = min(lower half of the clip, 64 px), width by the media aspect. Setting off (ADR-278 setting): no job, cache cleared, lower half blank. Alternatives: one ffmpeg child per thumbnail (rejected: process start cost, cap 3..6); thumbnails on disk (rejected: disk use, R-T3); effects drawn (rejected by REQ-369 and business key decision). Reason: bounded memory and processes, UI never waits (REQ-032 pattern), reuse of the zoom-independent cache.

ADR-278 (planned) setting for picture strips. Choice: program setting `show_picture_strips` (bool, default true) in settings.json version 2 as an additive field (ADR-028/040/044 pattern); switch in Settings > Interface (src/settings/interface.rs); not a project field (REQ-252). Alternatives: project setting (rejected by REQ-370). Reason: the choice follows the machine, not the project.

ADR-279 (planned) project as media. Choice: a new media kind `MediaKind::Project { source: PathBuf }` (src/media.rs). Import reads the source with the bounded project loader (16 MiB, ADR-191 path) and refuses an unreadable file or missing sources with a message naming the file. Self-import check: the source's own project-media references are followed recursively (depth at most 8); the importing project's path appearing in the chain is refused (REQ-373). The item is a normal video media whose file is an intermediate rendered by the export pipeline (src/export.rs `run`) with a fixed preset: source frame size and rate, H.264 libx264 `-crf 12 -preset veryfast`, AAC 256 kbit/s, stereo; written to the private work folder (0700, ADR-033) as `<key>.mkv.partial` then renamed; key = SHA-256 of the source file bytes (sha2, present). The item keeps `from: source path`. On reopen, a changed key (or missing intermediate) starts a rebuild in `Priority::Export`; the item shows "rendering" until done (REQ-032 non-blocking). Name patterns added to src/scratch.rs so a crash clean-up removes them. Alternatives: a live nested graph in the preview (rejected: decodes every nested source at once, cycles harder, slower preview); a copy of the timeline inside the project (rejected: the business link semantics, size); keeping the source bytes in the project (rejected: size, privacy). Reason: one media path for preview, proxy, export and every edit (split, fades, text, overlap) with the existing code. Consequences: a re-encode (near lossless, one extra generation), import time equal to a short export, disk use of the intermediate (not measured yet), a source change is seen only on reopen (REQ-371, popup REQ-372). Risks R-T1, R-T2.

ADR-280 (planned) project format 16. Choice: `SCHEMA_VERSION` 16 (project.rs); loads 1..16; every save writes 16 (the ADR-244 pattern); newer refused and never written (REQ-029). The new media kind is the only change. Alternatives: write 16 only when a project media exists (rejected: two writers to test, a 15 file could be read by 3.1.x without knowing the kind); keep 15 and encode the item as a path (rejected: silent misread by 3.1.x). Reason: explicit refusal by old versions is the documented rule. Consequence: 3.2.0 projects do not open in 3.1.x (release note).

ADR-281 (planned) player playlist. Choice: src/playlist.rs of the player: `items: Vec<PathBuf>` stays; a parallel `durations: Vec<Option<Micros>>` (aligned with items, filled by `Priority::Probe` ffprobe jobs, one per item, cached until the list changes); operations `move_up(i)`, `move_down(i)`, `remove(i)` keep `current` on the same video (removing the playing one selects the next at the same index; after the last one, stop: `current = None`). Menu: a top-level "Playlist" menu (player/src/ui.rs `menu_bar`) with the items in order, each with move up, move down and remove. Total: sum of the durations when every item is known; shown in brackets `[hh:mm:ss]` after the current video's total only when two or more items are in the list; shows `[--:--:--]` until all are known (TECHNICAL, changes R-T6 wording). Alternatives: a separate window (rejected: menu requested); durations read at Start only (rejected: total would appear late). Reason: each file is probed once, the list order is the single source of Next and Previous.

ADR-282 (planned) screenshot. Choice: "Take screenshot" command in the player's File menu (player/src/ui.rs `menu_bar`), issuing `egui::ViewportCommand::Screenshot`; the returned image is cropped to the rectangle where the picture is drawn (subtitle lines and the 360 view as on screen); PNG encoded by the `image` crate with its `png` feature (png 0.18.1 is already in the tree through eframe, no new crate); save dialog through rfd (existing) with the directory from `directories::UserDirs::picture_dir()` (fallback home) and the file name `<video stem> <hh.mm.ss.mmm>.png` (dots: no colon in Windows names). Nothing is written next to the video. Alternatives: decode the frame with ffmpeg and redraw subtitles and the 360 view (rejected: two renderers that can differ); write the file to a temporary and copy (rejected: no gain). Reason: the picture is exactly what the user sees, the cost is the readback of one frame. Caveat: the readback shows the frame drawn at that moment; the name uses the player position of that frame.

ADR-283 (planned) recorder noise (Linux first, all platforms, REQ-377). Root cause (confirmed read-only, 2026-11-28, Linux machine of the report: PipeWire 1.0.5 with its PulseAudio layer, WirePlumber): the default source is the internal analog microphone of an HDA Intel PCH (ALC295). Its ALSA "Capture Volume" is at 63 of 63 (its dB scale: -17.25 dB + 63 x 0.75 dB = +30 dB), "Internal Mic Boost Volume" at 2 of 3 (+20 dB), the PipeWire source volume at 76 % (-7 dB). The recorder reads `@DEFAULT_SOURCE@` through ffmpeg `-f pulse` (48000 Hz, 2 channels, screen-spy/src/plan.rs `sound_input`) and mixes it with `amix normalize=0` and `alimiter`: no gain control, no filter, so the amplified hiss and fan noise reach the file. The monitor input (computer sound) is clean. Choice: a noise reduction filter on the mixed track before `alimiter`: `afftdn` (FFmpeg FFT denoiser, present in the bundled ffmpeg and in the editor's CLEAN_AUDIO, ADR-080), start values `nr=25:nf=-20:tn=0:rf=-60`, tuned once on a synthetic fixture (noise at a fixed seed plus speech-like bursts, generated in the test, no binary file) against REQ-377 (quiet parts at least 10 dB lower, speech within 3 dB). The filter adds delay (FFT window): the picture branch `[rec]` is delayed by the measured delay L (assumed to be about one FFT window, about 0.1 s; measured, not assumed, by the PE) (`setpts=PTS+L/TB`, value fixed in code after the fixture test measures it), so picture and sound stay in sync. The recorder keeps its own constant (screen-spy does not depend on the editor's render module for it). Alternatives: noise reduction on the microphone input only (kept as the fallback if R-T4 fails: keeps computer sound untouched); `anlmdn` and `arnndn` (rejected by ADR-080; arnndn needs a model file); a high-pass or low-pass for hum only (does not remove hiss); changing the system mixer or PipeWire volume (rejected: changes the user's system settings without asking); a hardware or driver setting in code (none). Reason: the same filter as the editor (tested, bundled), no new dependency, no system change.

ADR-284 open (not decided): the echo of the computer sound picked up by the microphone (speakers and microphone of the same computer) is not addressed; echo cancellation (PipeWire or PulseAudio module) would be a system setting. Listed in R-A3.
