# Architecture: picture (frame, Scale, Move, LUT, overlays)

Part of [Architecture](architecture.md). Requirements: [frame](business-frame.md), [LUT](business-lut.md), [overlap media](business-overlap.md). Module map: [code-architecture](code-architecture.md).

## Frame and composition (Change aspect, Scale, Move)
- **Change aspect** (one per project) sets the shape (4:3, 16:9, 9:16, or a custom ratio 1:4 to 4:1, REQ-285, ADR-193), the fit (on width or height; sides even) and the empty space (a colour, or a blurred copy of the video: Low, Medium (default), High; REQ-284). The base size is the format's size or the Export preset. Example: 1600x1200 to 9:16 gives 1600x2844 (fit on width) or 675x1200 (fit on height). The longer side is capped at **4096 px** (decided 2026-11-19).
- The picture is the source fitted into the base size, never stretched; a longer part is cut equally from both sides, a shorter one is centred on the background.
- **Composition per flat clip (and per camera view of 360), identical in preview and export:** 1. the picture at base size; 2. the background at frame size (colour, or the video scaled to cover and blurred on a copy at 1/8 of each side, `BLUR_DIVISOR` 8, ADR-180; a clip's own Change aspect uses the same chain, REQ-335 planned 3.1.0 fixes the 2.3.0 gap, ADR-250); 3. the picture scaled and moved by the clip's Scale and Move; 4. Fade IN/OUT over the background; 5. subtitle lines and text items last, at fractions of the frame.
- **Clip Change aspect (REQ-286):** the clip's own frame (`timeline::clip_aspects`), padded into the project frame; the clip is re-encoded. Dropping the row on a clip applies it there (REQ-288). Fit and empty space per clip (REQ-326, 2.3.0) offer the whole-video choices (`ui::frame_popups::aspect_fields`, `popups::clip_aspect_rows`); the first choice is Fit on width and black.
- Any Change aspect, Scale, Move or LUT makes the export a re-encode, even at defaults. The 360 whole-sphere export ignores Change aspect, Scale and Move (the output keeps its usual size); the flat camera view applies them.

### Scale and Move keyframes
- A clip has at most one Scale and one Move, each a list of keyframes (`Key<T>`, at most **200**); a new one starts with one keyframe (100 % or the centre). Linear between keyframes; the nearest value before the first and after the last.
- Keys are in the clip's **source time** (as the 360 points of view): trim, split and cut never delete them; keys outside the part in use are hidden, not lost, and still shape the path. Scale is permille of the base size (100 to 4000; 100 = 100 %); Move is the centre in 1/10000 of the frame (5000, 5000 = centre; 0 to 10000). A corner drag keeps the opposite corner fixed through a hidden centre offset in the Scale key (ADR-096); Move is never changed by Scale drags.
- Split and copy keep keys; merge needs equal keys (ADR-101).
- **Whole video (1.6.1, built 2.2.0):** no whole-video Scale or Move in the format (REQ-148). A double-click gives each clip its own copy (source time, from the clip's start, one undo step); the whole-video popup shows the first clip's keys over the longest clip and applies each change to every copy at the same clip time. A change on one clip changes only that clip (known limit: the popup then shows the first clip's keys only). Conversion of format 8: [projects](architecture-projects.md#conversions-when-opening-in-memory).

### Filter graph and preview
- Scale: a per-frame size from the keys (`scale`); Move: a per-frame position for `overlay`. Piecewise-linear expressions from numbers only; no project text enters a filter; a long graph goes through a script file (ADR-099). The colour is validated `#RRGGBB` and written `0xRRGGBB` (ADR-100).
- ffmpeg 6.1.1 accepted the time-dependent sizes in the spike; the bundled 9.x build is not yet checked. Fallback: a command file with changed values, as for the 360 camera.
- Preview: a box with square corner handles (Scale) and a round Move target at the centre. Hit priority (ADR-103): subtitle and text boxes, Scale corners, visible edges (REQ-145: an edge drag scales proportionally, 10 % to 400 %), the Move target, the picture (camera drag on 360). A drag is live; one drag is one undo step. The keyframe popup is non-modal.

## Apply LUT
- A colour effect, one per clip and one for the whole video. The project stores the path (and a copy since 2.0.4, below). The file is checked when chosen and at each export. `ffmpeg` applies it with `lut3d interp=tetrahedral` in the same graph as preview and export.
- **Formats:** `.cube` (UTF-8), `.3dl`, `.csp` (REQ-290, 291). Keywords `LUT_3D_SIZE`/`LUT_1D_SIZE`, `TITLE`, `DOMAIN_MIN/MAX` (only 0..1 in the core; a `.cube` range is applied when read). 1D tables are sampled into a size-33 cube. Values finite, clamped to 0..1. Mixed kinds, unknown numbers or bad counts refused with a message; the project is unchanged.
- **Limits:** 2.0.4: 16 MiB, size 2 to 65. 2.1.0: streamed in one pass (1 MiB buffer), lines at most 256 bytes, exactly size^3 entries, size 2 to 256, file at most 512 MiB (`MAX_3D` 256, `MAX_BYTES` 512 MiB, `MAX_LINE` 256, `MAX_WHOLE` 64 MiB for `.3dl`/`.csp`). Memory 6 bytes a point (100.7 MB at 256, 17.9 MB at 144); cache 192 MB LRU.
- **Loading and preparation (2.1.0, 2.2.0):** a file above 1 MiB not cached is read by a background `Load` ("Reading the LUT file... N %"); `Prep` ("Preparing LUT N %": read and write 60 %, then up to 95 %) writes a Work copy `lut-<hash16>.cube` (streamed, temp then rename) shared by clips, preview and export. The preview shows the picture without the LUT until it is ready (about 12 s to the first graded frame at 256 points, not gated). A changing file is refused; another choice or closing cancels and removes the partial copy. The user's path never enters a filter.
- **Strength (REQ-289, ADR-191):** 0 to 100 % (default 100), `lut.rs` `with_strength` mixes each entry with the identity.
- **Copies (REQ-293, ADR-191):** the normalised cube as text in `lut_copies`, keyed by SHA-256; at most 20 MB per copy and 64 MiB per project; above that only the path (REQ-301). **Favourites (REQ-294):** up to 20 files, in settings only.
- **Missing file (REQ-292):** the project opens and the status line names the file; the LUT is not shown; at export a three-button modal: Find the LUT file, Export without the LUT (this export only), Cancel. The project keeps the LUT. A changed file is re-hashed (SHA-256 of the validated table) so the preview never mixes old and new.
- **Order:** the whole-video LUT before the clip LUT; after the clip's Scale and before the background composition; in 360 video export after the projection. From 2.1.0 the LUT is a movable row of Applied effects ([effects](architecture-effects.md)).
- Targets (estimates): parse 144 points at most 2 s, 256 points at most 6 s; Work copy of 256 points at most 3 s; the window frame at most 200 ms while loading. A 1080p preview with a 33-point LUT within 20 % of the playback rate without one (assumption).

## Picture overlays and overlap media (2.3.0, built)
- **Overlap** (REQ-325, 327 to 331): stored in its **clip**: `Timeline.clip_overlaps: Vec<ClipOverlaps { clip, items }>` and `next_overlap_id`, written when not empty (the plan put it in `Clip`, a `Copy` type: deviation). Fields: file path (text; the file is not copied), kind Still (PNG) or Motion (GIF, video), `from` relative to the clip start, `len`, place and size in permille, `reshaped`, `src_w`/`src_h`. Several per clip; they may overlap in time and are drawn in order.
- **Editing:** a ripple moves the overlap with its clip; trim or split cuts it to the kept part (split gives the right half a new id); an edit that leaves no part removes it. `AppState::edit` lists the losses; an unconfirmed loss changes nothing and returns `REMOVAL_ASK`; `Modal::RemoveOverlaps(n)` asks once (REQ-329; Cancel changes nothing; one undo restores all). Change speed rescales the times (old/new speed), no warning. Lane drags clamped; minimum length 0.1 s (assumption).
- **Commands (`app/overlap.rs`):** `AddOverlap(path)` (clip under the playhead; 3 s cut to the clip; file ratio; selected; on top; no clip = status line), `SetOverlapBox`, `SetOverlapTimes`, `RemoveOverlap`, `SelectOverlap`. "Add media" (REQ-324) is the same action as File > Import media...
- **Shape (REQ-327):** Ctrl (Command) on an edge changes the ratio: a MOV is cropped to the box (cover), a GIF or PNG is stretched. Otherwise the media's ratio holds.
- **Once, then transparent (REQ-328):** a GIF or MOV plays once from its start, without sound; `overlay eof_action=pass` passes the picture through afterwards; a PNG stays (looped, `shortest=1`). Video stream only.
- **Render paths:** (1) default order: drawn after the concat, as picture items (a project without overlaps keeps its argument list); (2) changed order: `OverlayStep::Pic` in clip time, step builder; (3) preview: the same plan, still updated for the latest frame. Never hardware-decoded (`preview::input_codecs`); the export never uses hardware decoding. The 360 whole-sphere export draws no overlap.
- **Size:** `picture::read_overlay` reads PNG and GIF headers (GIF screen size, 13 bytes); other formats by ffprobe; over **16 megapixels** (REQ-316, `MAX_PICTURE_PIXELS` 16,000,000) refused when added and checked at use (`picture::overlay_usable`; a file that became too large counts as missing). Files above 1920x1080 are drawn at half size in the preview only. Decoding costs about 64 MB per frame at 16 MP RGBA (measured by the developer).
- **Alpha:** PNG and GIF keep transparency through the bundled ffmpeg; MOV keeps alpha in qtrle and ProRes 4444 (assumption; fixtures `tests/fixtures/overlay/alpha.{png,gif,mov}`: 64x64 red square, 1 s GIF and MOV; test `tests/ffmpeg_integration/v23overlap.rs`). A codec without alpha is drawn opaque.
- **Interface:** Effects row "Overlap media" (2.3.0 shared the first row with Add Text; its own row after Add Text from 3.1.0, REQ-336, ADR-251), `ui/overlap_lane.rs`, `ui/overlap_box.rs` (click selects, drag moves, edges and corners resize, one command on release), Applied rows `Overlap: <file>`.
- **Limits:** no keyframes, rotation, own video track or MOV sound; not in 360 export. Targets: at most 10 % more preview frame time for a 1080p still; export at most 1.5 times without (estimate, not gated).

## Project formats of the picture data
Format 7 (1.5.0): Change aspect and Scale/Move with keys per clip and for the video. Format 8 (1.6.0): LUT (`whole_lut`, `clip_luts`). Format 9 (1.6.1): fades as clip flags; no whole-video Scale, Move or LUT. Format 12 (2.1.0): text shadow and related fields. Format 13 (2.2.0): the order rows. Format 14 (2.3.0, ADR-230): overlaps; 13 converted in memory (ADR-241). Damaged values are corrected on load with a note (scale 10 % to 400 %, centre to the frame, duplicate times dropped, keys outside the media dropped, more than 200 cut, unknown shapes or colours replaced). Full list: [projects](architecture-projects.md).

## Security
- Inputs checked: keyframe numbers within ranges; shapes and fits from closed lists; colours `#RRGGBB`; LUT paths UTF-8 without control characters; LUT and overlay files are untrusted (bounded reads, validated tables, fixed work names, size checks before decoding, paths never in filter text).
- Frame sizes come only from the base size and the shape, never from numbers in a file; the 4096 px cap bounds memory and encoder load.
- No network, no unsafe code, no new crate. ffmpeg core filters used: `color`, `split`, `scale`, `boxblur`, `overlay`, `format`, `lut3d`, `alphamerge`, `eof_action`.

## Tests
- Pure: keyframe values (hold, linear, limits, unique times); frame sizes from the requirement examples; even sides and the 4096 cap; timeline split, copy, merge, remove; format 7 round trip; damaged values; LUT parse refusals, limits, NaN and infinity, random bytes; overlap rules.
- Command: expressions and filter text for one and several keys; no-effect commands unchanged (golden); 360 export without effects; re-encode forced.
- Real ffmpeg: frame size; colour in the empty space; blurred border without a sharp edge; Scale 50 % shows background; Move 10 % moves 10 % (within 1 %); Scale 150 % at 2 s between 100 % at 0 s and 200 % at 4 s; a 3D LUT (channel swap) gives exact colours; 360 export shows LUT colours; overlay alpha in preview and export.

## Risks
Listed in [risks](architecture-risks.md#technical-risks): time-dependent sizes on the 9.x build, large frames and hardware encoders, small keyframe popups, texts not following Scale or Move, the overlay limits, colour round trip.
