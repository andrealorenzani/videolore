# Business — Export

Back to the [index](business.md).

## Features
- Automatic output format by default. Since 1.4.0 an Export dialog chooses what to export (full video, only audio or only subtitles), the file location and name, the video format and the audio format; each format has "Same as source" as its reset (see [Export dialog](#export-dialog-140)).
- As fast as possible: no re-encoding when it is not needed.
- Progress and cancel; a cancelled export leaves no partial file.
- Music and subtitles are included in the exported file (subtitles are burned into the picture).
- HEVC files play on Apple devices.
- (1.2.0) Subtitles can also be saved as a separate `.srt` file with File > Export subtitles (.srt)… (REQ-088, see [Subtitles](business-subtitles.md)).
- (1.3.0) Text items are burned into the picture like subtitles (REQ-111); a project with a text item is re-encoded. Since 1.4.0 the Export dialog offers, for a project whose clips are all 360, a 360 video that keeps the whole sphere or the flat camera view of 1.2.6 (REQ-103, REQ-122, see [Boxes on the picture and 360 video](business-picture.md)).
- (0.4.0) **Faster export** with the computer's video hardware (NVIDIA, Intel, AMD, Apple), chosen in Settings. If the hardware is missing or fails, the normal method is used automatically and the result is always a correct file.

## Requirements
- REQ-021 (implemented): Export shows progress and can be cancelled; a cancelled export leaves no partial file.
- REQ-022 (implemented): The output format is chosen automatically unless the Export dialog chooses one (REQ-120, REQ-121): if all clips share the same format it is kept; otherwise the lowest by pixel count, then frame rate, then bitrate is used, with letterboxing and never stretching.
- REQ-023 (implemented): Export does as little processing as possible: stream copy (no re-encode) when all clips share an identical format, there are no effects (fades between clips or at the start or end of the video, subtitles, text items, music, video sound level other than 100% or muted, a clip volume other than 100% or a muted clip) and every cut starts on a keyframe, and the Export dialog keeps "Same as source" for both video and audio (REQ-120, REQ-121) with no clip having Clean audio (REQ-114); otherwise a single re-encode pass, always frame-accurate.
- REQ-036 (implemented): Exported HEVC video in MP4 or MOV carries the Apple-compatible tag (hvc1), both with stream copy and with re-encode.
- REQ-037 (implemented): A timeline of 200 segments cut from one source exports successfully and frame-accurately.

### Export dialog (1.4.0)
- REQ-118 (implemented): **Export** (File > Export…, the Export toolbar button and Ctrl/Cmd+E) opens a dialog instead of exporting at once. Its **export file** field holds the location and the file name, with a small "..." button that opens a folder chooser. The first time, the name is the project's name in the project's folder; if the project has no folder yet, the folder of the last export of the session, else the user's documents folder. The extension follows the chosen format (.mp4, .mov, .m4a, .mp3 or .srt) and is set automatically. The dialog has an **Export** button and Cancel. Export is disabled, with the reason shown, when the name is empty or invalid or the folder does not exist or cannot be written. If the file exists, a confirmation asks before it is replaced. The choices are kept for the session only; they are not saved in the project or in Settings. Acceptance: Ctrl/Cmd+E and File > Export… open the dialog; "..." changes the folder; a missing folder disables Export with its reason; an existing file asks first; Cancel writes nothing; a second opening in the same session shows the last choices.
- REQ-119 (implemented): The dialog's **mode** is **Full video** (the export of REQ-021 to REQ-023 with the chosen formats), **Only audio** (the sound of the whole timeline as one audio file: video sound, music, volumes and Clean audio, in the audio format of REQ-121; no video fields) or **Only subtitles (.srt)** (the file of REQ-088). Fields that do not apply to the mode are greyed out with a reason; Only subtitles is greyed out with "No subtitles on the timeline" when there are none. File > Export subtitles (.srt)… keeps working. Acceptance: Only audio of a 10 s timeline with music gives a 10 s audio file that contains the music at its volume; Only subtitles gives the same text as File > Export subtitles (.srt)…; without subtitles the mode shows its reason.
- REQ-120 (implemented): **Video format** (Full video only) is a dropdown whose entries read like "1920x1080 25fps, libx264, .mp4". Its first entry, **Same as source**, is the automatic result of REQ-022, with stream copy when REQ-023 allows it. The other entries are a fixed list of 12 presets (resolution, frame rate, H.264 or HEVC, MP4 or MOV); a preset is offered only when the bundled ffmpeg has its encoder. A preset is always re-encoded and can use the hardware export (REQ-055). A 360 video (REQ-122, REQ-103) keeps the sphere's own size and ignores the preset. A small reset button sets "Same as source". Pictures keep letterboxing and are never stretched (REQ-022); HEVC in MP4 or MOV carries hvc1 (REQ-036). Acceptance: the entries read as in the example; choosing 1280x720 25fps libx264 .mp4 gives a file of that size, frame rate and codec; reset returns "Same as source"; with "Same as source", identical clips and no effects, nothing is re-encoded.
- REQ-121 (implemented): **Audio format** (Full video and Only audio) is a dropdown with **Same as source** (today's automatic audio: the encoder of the source's audio codec, AAC by default; stream copy when REQ-023 allows; Only audio writes an .m4a file), **aac** (.m4a) and **mp3** (offered only when the bundled ffmpeg has its encoder). A small reset button sets "Same as source". A chosen audio format always re-encodes the audio. Acceptance: the aac file decodes with the timeline length; reset returns "Same as source"; mp3, when offered, gives an .mp3 file.
- REQ-122 (implemented): The **360 choice** of the dialog (Full video only) appears only for a project whose video clips are all 360 clips: **360 video** or **Flat camera view** (REQ-103). A project without 360 clips and a project that mixes 360 and flat clips show no 360 choice; a mixed project exports as a flat camera view, without a message. Acceptance: an all-360 project shows the choice; a mixed project and a project without 360 clips do not; the mixed project exports flat.

### Faster export (0.4.0)
- REQ-055 (implemented): Hardware export with silent fallback. When Export is "Faster" and the export needs re-encoding to H.264 or HEVC, videolore uses the working video hardware found by the background check (REQ-061): NVIDIA (Windows, Linux), Intel Quick Sync (Windows, Linux), AMD (Windows; on Linux AMD and Intel are also reached through VA-API) and Apple VideoToolbox (macOS). If there is no working hardware, or the hardware run ends with an error, crashes, makes no progress for 30 seconds, or fails the output check (REQ-063), the export is automatically redone with the normal method, with no error message; the user always gets a correct file. Acceptance (automated, simulated hardware, for each vendor): missing hardware, error exit, crash, stall and bad output each end with a finished file in the same format as Best quality and with the correct number of frames; no error is shown; no temporary file remains (REQ-059). Cancelling during the hardware run, the check or the redo leaves no partial file (REQ-021) and never starts a redo. With Export = Best quality the hardware is never used.
- REQ-060 (implemented): "Export" choice in Settings. The main section of Settings gains **Export: Faster / Best quality**, with one-line explanations. Faster: "Uses your computer's video hardware when it can. Often quicker, but not on every computer; files may be a little larger." Best quality: "Uses the normal method. Slower, best picture for the file size." The recommendation is Best quality on every computer; Faster is opt-in. Faster is never greyed out; when the check found no usable hardware, its explanation adds "This computer has no video hardware videolore can use, so both choices give the same result." A change applies to the next export; a running export is not restarted. Acceptance: the main section still contains none of the words banned by REQ-046; choosing Faster makes the status "Custom settings"; "Use recommended settings" (REQ-047) sets it back to Best quality; the choice is saved with the program settings, never in a project; the first start (REQ-045) saves Best quality.
- REQ-061 (implemented): Background hardware check. videolore checks in the background which video hardware works, separately for H.264 and HEVC, with a short test per candidate. Each candidate first gets 1 second; if that test runs out of time (for example because the computer is busy), the same candidate gets one more try of up to 4 seconds before the next candidate is tried, so the preference order never changes. The whole check takes at most 10 seconds (time spent waiting for a free process slot is not counted). If the answer is uncertain, meaning no working hardware was found for a format and one of its candidates ran out of time, videolore repeats the whole check once by itself; meanwhile the first answer is used. A test that runs out of time is never remembered as a hardware failure (REQ-064). The check can be cancelled. It never delays the window, start-up or preview, uses no network, and its processes count within the process limit (REQ-033). The check runs only when it is needed: at start-up when the saved choice is Faster, when the user switches to Faster, on "Use recommended settings", on "Try video hardware again", and when the user-chosen ffmpeg changes while Faster is selected. With Best quality nothing runs. An export started before the check has finished uses the normal method. Preference order: Windows NVIDIA, then Intel, then AMD; Linux NVIDIA, then Intel Quick Sync, then VA-API; macOS VideoToolbox. The Advanced section shows which video hardware works for each format and which method the last export used. Acceptance (simulated hardware): start-up is no slower than allowed by QG-01; the time limits are respected (1 second first try, one 4-second retry per candidate, 10 seconds in total); hardware that answers only after the first second, as on a busy computer, is still found and keeps its place in the preference order; an uncertain answer triggers exactly one automatic repeat of the check; a test that runs out of time never turns the hardware off for later exports; the same set of working hardware always gives the same choice; a user-chosen ffmpeg (REQ-030) is checked the same way.
- REQ-062 (implemented): Same output as Best quality. A hardware export matches the Best quality result in container, video format, resolution, frame rate, picture format (8-bit 4:2:0), audio, number of frames and timing, letterboxing, fades, music and burned-in subtitles (REQ-022 and REQ-037 still hold). HEVC in MP4 or MOV carries the hvc1 tag (REQ-036). The Export choice never changes whether stream copy is used (REQ-023): stream-copy exports are identical byte for byte with either choice. Formats other than H.264 and HEVC always use the normal method. Acceptance: stream-copy output identical under both choices; for each simulated vendor the export has the same format as Best quality and the hvc1 tag for HEVC; real hardware is verified through QG-05.
- REQ-063 (implemented): Output check against silent hardware faults. After every hardware export, before the file appears at its destination, videolore checks that the whole file decodes without errors; that the number of frames, duration, resolution and frame rate are as expected; and that three sample frames (near the start, middle and end) are close to the same frames rendered with the normal method. If the check fails, the REQ-055 redo runs. Progress shows the check as part of the export. Acceptance: a simulated hardware run that ends without error but writes an empty file, a truncated file, missing frames, the wrong picture size, or green or garbage frames is always detected and followed by a correct file made with the normal method; a correct hardware file passes.
- REQ-064 (implemented): Remember failing hardware. After a hardware failure for a format on this computer, later exports in that format go straight to the normal method, until the computer's characteristics change, videolore is updated to a new version, the check picks a different kind of video hardware, the user presses "Use recommended settings" (which also runs the check again), or the user presses "Try video hardware again" in Advanced. Advanced shows "Video hardware turned off after a problem". A failure is remembered only when the redo with the normal method succeeded; cancelling never counts as a failure. Acceptance (simulated): after a failure the next export skips the hardware; each reset brings the hardware attempt back.
- REQ-065 (implemented): Upgrade from 0.3.x. A 0.3.x settings file without the Export choice loads with Export = Best quality, without any notice, and the "recommended / custom" status stays as it was before the upgrade. Upgrades from 0.2.x (REQ-049) and damaged settings (REQ-057) also get Best quality. Acceptance: a 0.3.0 settings file with recommended settings stays "Using recommended settings"; one with custom settings stays "Custom settings"; both load Export = Best quality.

The real-hardware check of this feature is the quality goal QG-05, in [Settings, performance and safety](business-performance.md#quality-goals).

## Key decisions
- (1.4.0) Output format is automatic by default ("Same as source"). The Export dialog (REQ-118 to REQ-122) lets the user choose the video and audio format, the mode and the location; this replaces the earlier decision of no export dialog. The choices are not a set of technical settings: only fixed presets and "Same as source".
- Stream copy is used only when the result is guaranteed frame-accurate; correctness comes before speed.
- Changing the video audio volume (or muting it) also requires re-encoding, like music and subtitles.
- H.264 and HEVC export are available with the bundled ffmpeg; output formats are the same as in 0.1.3.
- (0.4.0) Hardware export is built for every vendor (NVIDIA, Intel, AMD, Linux VA-API, Apple), protected by the automatic fallback and the output check; combinations not verified on real hardware are listed as known limitations.
- (0.4.0) **Best quality is the default everywhere; Faster is opt-in.** Upgrades from 0.3.x load as Best quality, so nothing changes until the user chooses Faster.
- (0.4.0) Every hardware result is checked (full decode, frame count and details, three sample frames compared with a normal render), because some driver faults produce bad video without reporting an error.
- (0.4.0) Quality target for Faster: at most 3 VMAF points below Best quality, and files at most 1.5 times the Best quality size (checked by hand, QG-05).
- (0.4.0) Only H.264 and HEVC use hardware: they are the formats with the broadest hardware support.
- (0.4.0) The hardware aims at the same average bitrate as the normal method, so file sizes stay close to Best quality. If the source bitrate is unknown, the normal method is used.
- (0.4.0) Exception, Linux VA-API (Intel and AMD through the system driver): Ubuntu's free Intel driver refuses bitrate control, so VA-API uses a constant-quality mode with size protection: if the hardware file is more than 1.5 times the size expected for Best quality, the export is redone with the normal method. This is not counted as a hardware problem (REQ-064 does not remember it).
- (0.4.0) The Faster explanation says "often quicker, but not on every computer" instead of "much quicker": on integrated graphics the hardware export plus its output check was measured to be sometimes slower than Best quality (QG-05).
- (0.4.0) The fallback is silent: there is no message; the method actually used is shown in Settings, Advanced. When a redo happens, the progress bar goes back to the start once.
- (0.4.0) The hardware check runs only when Faster is selected or the user asks for it, so computers using Best quality do no extra work and graphics cards on laptops are not woken up for nothing.
- (0.4.0) The words "hardware" and "video hardware" are allowed in the main part of Settings; "GPU" and "encoder" are still not.

## Known limitations (0.4.0)
- **NVIDIA** needs graphics driver 610 or newer. With an older driver the check fails quickly, the normal method is used, and Advanced says why ("graphics driver too old").
- **Linux, Intel and AMD**: hardware export needs the system's video acceleration library (libva) and the vendor driver (Intel media driver or Mesa). **Fedora's default Mesa has no H.264/HEVC encoding**; AMD and Intel users there need the RPM Fusion "freeworld" VA drivers (for example `mesa-va-drivers-freeworld`). Without them the normal method is used.
- **Linux, Intel Quick Sync** uses the default graphics device; an Intel graphics card on another device is reached through VA-API instead.
- On computers with more than one graphics card, NVIDIA is always preferred; the user cannot pick a card.
- Combinations of operating system and graphics vendor that have not been verified on real hardware (QG-05) are recorded as unverified with the QG-05 results in the developer documentation; they are still protected by the fallback and the output check.
- The output check samples only three points of the video; damage limited to frames between them could pass unnoticed (checked by hand in QG-05).
- **Linux, Intel and AMD with the bundled ffmpeg** need system libva 2.21 or newer. On older systems (Ubuntu 24.04 ships 2.20) VA-API and Quick Sync are skipped without any crash, the normal method is used, and Advanced says "needs a newer system video library (libva 2.21 or newer)". A user-chosen ffmpeg built for the system can still use the hardware.
- **Linux, Intel, HEVC**: on the measured Intel driver (Ubuntu 24.04, Intel Iris Plus G7) hardware HEVC is broken; the output check catches it and the normal method makes the file.
- **Faster is not always faster.** Measured on Linux with Intel integrated graphics (Iris Plus G7, 0.4.0): Faster ranged from 14% quicker to 41% slower than Best quality, because the hardware export plus the output check is not quicker than the normal method on that graphics. Size and quality targets were met. Speed on other computers is still to be measured (the estimate for dedicated graphics cards is 20–45% less time at 1080p, assumption).
- A driver fault that freezes the whole computer cannot be prevented by videolore.

## Known limitations (1.4.0)
- The format choices are a fixed list of presets; resolutions, frame rates, bitrates or codecs outside the list cannot be chosen.
- The Export dialog remembers its choices for the session only; they are not stored in the project.
- A 360 video ignores the video format presets: it keeps the sphere's own size.

## Out of scope
- (1.4.0) Remembering export choices in the project or in Settings; custom resolutions, frame rates, bitrates, quality values or encoder options.
- Separate subtitle files (SRT/VTT) or switchable subtitles; subtitles are always burned in.
- Direct upload to social networks.
- (0.4.0) Video hardware for preview copies, preview playback, effects, subtitles or decoding; preview copies stay on the normal method.
- (0.4.0) Hardware AV1 or VP9 encoding (those formats always use the normal method).
- (0.4.0) Choosing a specific graphics card or vendor; per-vendor quality sliders; any technical export setting beyond the presets of the Export dialog.
- (0.4.0) AMD hardware through AMD's own interface on Linux (AMD on Linux goes through VA-API); Intel Macs; ARM Windows and Linux.
- (0.4.0) Bundling or installing graphics drivers.
- (0.4.0) A visible message when the fallback was used (shown only in Advanced).
- (0.4.0) Making Faster the default.
- (0.4.0) Battery-aware behaviour.
