# Business — Settings, performance and safety

Back to the [index](business.md).

## Features
- **Automatic setup**: the first start looks at the computer and picks recommended settings; a short notice says so and closes by itself.
- **Settings window**: Edit > Settings… (Ctrl/Cmd+,) opens a window inside videolore with plain choices:
  - **Preview quality**: Automatic / Smoother / Original.
  - **Subtitle quality**: Fast / Balanced / Most accurate.
  - **How hard videolore works**: Light / Balanced / Maximum speed.
  - **Export**: Faster / Best quality (Best quality is the default; see [Export](business-export.md)).
  
  A status line says "Using recommended settings for this computer" or "Custom settings". Settings also shows the disk space of preview copies and speech files, with "Clear preview copies" and "Remove downloaded speech files". A collapsed "Advanced" section holds the user-chosen ffmpeg, paths, versions and origin of the bundled components, the video hardware status and "Try video hardware again".
- **Use recommended settings**: checks the computer again and restores the recommended choices.
- **More accurate subtitles**: two larger speech files (Balanced and Most accurate), downloaded only with the user's consent the first time they are needed.
- **Older processors**: on computers too old for automatic subtitles videolore says so in plain words; everything else works.
- **Safety**: damaged or hostile files cannot crash videolore, run other programs or write anywhere unexpected; downloads are checked; temporary files are private and cleaned up.

## Requirements

### Automatic setup
- REQ-045 (implemented): On first start (no settings file), on every operating system, videolore detects the computer and saves recommended values for every performance setting, then shows once a notice that closes by itself: "videolore has been set up for this computer. You can change this in Settings." Acceptance: the settings are created and the notice is shown once; on the second start there is no notice and no new detection (unless REQ-048 applies); detection takes at most 3 seconds, runs no long benchmark and uses no network; the same computer characteristics always give the same result.
- REQ-046 (implemented): Settings is a window inside videolore, opened from the Edit menu, with three plain-language choices: Preview quality (Automatic / Smoother / Original), Subtitle quality (Fast / Balanced / Most accurate) and How hard videolore works (Light / Balanced / Maximum speed), each with a one-line explanation, and a status line "Using recommended settings for this computer" or "Custom settings". A collapsed "Advanced" section holds the user-chosen ffmpeg and the paths, versions and origin of the bundled components. Acceptance: (a) the main section contains none of the words thread, core, proxy, codec, encoder, ffmpeg, AVX, CPU, GPU, model, quantised; (b) changes apply without restarting; (c) settings belong to the program, never to a project file; (d) choices this computer cannot use are greyed out with a plain reason. The main section also has the Export choice (REQ-060) and Advanced the video hardware status (REQ-061, REQ-064); acceptance (a) still applies.
- REQ-047 (implemented): A "Use recommended settings" button checks the computer again, resets the choices (Export back to Best quality, remembered hardware failures cleared, hardware check run again, REQ-064) and shows a plain summary of what changed, or "Already using the recommended settings". Acceptance: the result is exactly the first-start recommendation (REQ-045); the user-chosen ffmpeg, projects, preview copies and downloaded speech files are untouched; nothing is downloaded.
- REQ-048 (implemented): When the computer's characteristics differ from those saved: if the recommended settings were in use, they are recomputed silently and the setup notice of REQ-045 is shown; if the user had custom settings, they are kept and a notice offers "Use recommended settings" without blocking. Acceptance: both cases tested with simulated computer data.
- REQ-049 (implemented): Upgrading from 0.2.x behaves as a first start, except that: if preview copies had been switched off, Preview quality becomes Original; a user-chosen ffmpeg is kept; an already downloaded speech file is kept. Acceptance: a 0.2.2 settings file with preview copies off and a user-chosen ffmpeg loads as Original with the same ffmpeg; projects from 0.1.x and 0.2.x open identically (REQ-029).

### Performance
- REQ-050 (implemented): "How hard videolore works" controls all background work: how many ffmpeg processes run at once, and how many threads export, preview copies and speech recognition use. Light uses at most half of the computer's logical cores (at least 1) for each background job; Balanced is the usual recommendation and matches 0.2.2; Maximum speed may use all cores; videolore never configures more threads than the computer has. The exact mapping is in the [architecture](architecture.md). Acceptance: the mapping is tested at 1, 2, 4, 8, 16 and more cores and with less than 8 GB, 8 GB and 16 GB or more of memory; a change applies to the next job and running jobs are not restarted.
- REQ-051 (implemented): Preview quality replaces the 0.2.x on/off switch for preview copies: Automatic uses the rule of REQ-038; Smoother makes a preview copy of any source larger than 1280x720; Original never makes one. Acceptance: the decision is the same for the same inputs; the exported file is the same whatever the choice.
- REQ-052 (implemented): Subtitle quality has three levels: Fast uses the 0.2.x speech file (about 32 MB, never worse than 0.2.2); Balanced (about 190 MB) and Most accurate (about 574 MB) use larger, more accurate ones. The recommendation depends on the computer: Most accurate only where it runs reasonably fast, and levels needing more memory than the computer has are greyed out. A level's file is downloaded only when subtitles are generated with that level and the file is missing, after a consent dialog showing size and licence; the dialog offers "Use Fast instead (no download)" when the Fast file is present (for that run only), or "Download the Fast one instead" when nothing is installed; a local file can be chosen for each level. Afterwards everything works offline. Acceptance: on a reference clip the word error rate of each higher level is at most that of Fast; declining changes nothing; changing the level never regenerates subtitles by itself (REQ-044 applies when regenerating). Since 1.2.0 the chosen level also matches the words of a video's own subtitles to the speech (REQ-095), with the same consent.
- REQ-053 (implemented): Settings shows the disk space used by downloaded speech recognition files and a "Remove downloaded speech files" button (with confirmation); projects and their subtitles are untouched, and a file is downloaded again, with consent, when next needed. Acceptance: the shown size matches the disk; after removal the space is freed and existing subtitles still show and export.
- REQ-054 (implemented): Subtitle generation never crashes on older processors. On a processor without the features the speech engine needs (for example x86-64 processors without AVX2), "Generate subtitles" shows "This computer's processor is too old for automatic subtitles; you can still add subtitle lines by hand", no download is offered, and the three subtitle levels are greyed out with the same reason. Since 1.2.0 the subtitles already in a video can still be used there: their text and line timing are kept and the words of each line are spread evenly (REQ-095). Acceptance: with a simulated processor lacking the features there is no crash and the message is shown; the recommendation never picks a level that cannot run.
- Faster export with the computer's video hardware (REQ-055, REQ-060 to REQ-065) is in [Export](business-export.md) and [Faster hardware export](business-hardware-export.md).
- REQ-056 (implemented): The window stays responsive while busy: with an export and subtitle generation running together at any "How hard" level, play/pause, timeline scrolling and opening Settings keep reacting. Acceptance: in a test harness every input is handled and visible within 200 ms. REQ-032 is unchanged. Also covers dragging section borders (REQ-066), open effect popups (REQ-076), dragging an effect onto a clip and dragging a subtitle in the preview (REQ-095 matching running).

### Safety
- REQ-057 (implemented): Damaged or hostile project, settings or media files never crash videolore, never make it run another program, never make it write outside the folders chosen by the user or its own folders, and never modify sources. Damaged projects are refused with a clear message; damaged settings are replaced by the recommended settings, with a notice. Acceptance: a test set of bad files (invalid or truncated data, huge numbers, absolute or `..` paths, control characters in names, oversized files) passes all of the above. The set also covers damaged layout values and recent-projects lists (REQ-067, REQ-080: default layout or empty list, other settings kept, no notice), subtitle tracks inside media files (damaged or hostile text, names and languages) and the project values of REQ-094.
- REQ-058 (implemented): Speech recognition files are downloaded only from fixed, built-in secure (HTTPS) addresses and checked against their known fingerprint (SHA-256) before use; partial or wrong files are deleted. There is no other network access, no telemetry and no update check. Acceptance: tests for a wrong fingerprint, an interrupted download and a refused non-HTTPS address.
- REQ-059 (implemented): Temporary files (extracted audio, partial exports, partial preview copies, partial downloads) can be read only by the user, are removed when the work finishes or is cancelled, and leftovers from a crash are cleaned up at the next start. Acceptance: none remain after a cancel or after a simulated crash and restart; on Linux and macOS they are readable only by the user.

### Code structure (2.0.1)
- REQ-151 (implemented): The shared helpers (capped reading of project, settings and LUT files, atomic writing, private work folders, subtitle positions, language names, cache and speech-model file names) are in one common module. No behaviour changes: the same projects, settings and subtitle files open with the same result, the same file names are used and the same output is written. Acceptance: every existing test passes unchanged; a 2.0.0 project, settings file and cache folder work in 2.0.1 with no migration and no notice.
- REQ-152 (implemented): Damaged-file and temporary-file rules stay as they are: a damaged or oversized file is refused or replaced as in REQ-057, and temporary files are private and cleaned up as in REQ-059. Acceptance: the existing REQ-057 and REQ-059 tests pass unchanged.
- REQ-153 (implemented): For maintainers, the program's modules have no dependency cycle; the shared helpers do not depend back on the modules that use them. Acceptance: no module cycle remains (see [code architecture](code-architecture.md#cycles)), and an automatic check fails when a new cycle is added.

## Quality goals
Engineering targets, measured and reported for each development; they have no feature tests. The numbers are assumptions to be adjusted after measurement.
- **QG-01 Performance review**: every choice (processes, threads, speech engine and files, libraries, preview and export settings) is reviewed. At the recommended settings export time and Fast subtitle time are at most 5% above 0.2.2 on the same computer, and start-up is at most 0.5 s slower.
- **QG-02 Security upkeep**: the automatic build fails on a known vulnerability in a dependency unless documented as not affecting videolore; the bundled ffmpeg is the latest release.
- **QG-03 Faster tests**: at least 30% faster than 0.2.2, without removing or weakening tests, with line coverage of at least 85% and every implemented requirement tested. Result in 0.3.0: 25% faster.
- **QG-04 Clean automatic builds**: no deprecation warnings; the Linux build machine is pinned; the Linux packages run on current Ubuntu LTS and Fedora (REQ-040).
- **QG-05 Real-hardware check of Faster export** (0.4.0): hardware export is checked by hand on Windows (NVIDIA, Intel, AMD), Linux (NVIDIA proprietary driver, Intel, AMD) and macOS (Apple Silicon). A reference project (mixed formats with letterboxing, 50 or more cuts, fades, music, subtitles) is exported in H.264 and HEVC with Faster and Best quality, and: a. Advanced shows the hardware was used; b. format and frame count are identical to Best quality; c. HEVC has the hvc1 tag and plays in QuickTime and on an iPhone; d. no blocking, banding, colour shift or green frames; e. quality score at most 3 VMAF points below Best quality; f. file at most 1.5 times the Best quality size; g. total time including the output check at least 40% lower than Best quality at 1080p (assumption; a measured target, not a release gate); h. with the hardware forced to fail, a correct file is still produced. Results per release are in the developer documentation.
  - Result in 0.4.0, Intel Iris Plus G7 (Ubuntu 24.04, system ffmpeg, VA-API H.264): quality and size met; time not met (from 14% quicker to 41% slower than Best quality). With the bundled ffmpeg the hardware is skipped (libva 2.20, 2.21 needed). Later measurements: see [Faster hardware export](business-hardware-export.md) and REQ-315.
- **QG-06 Shorter automatic builds** (1.6.1): the build and test run on GitHub finish sooner; only the system packages needed are installed. Target (assumption): at least 30% less time than the 1.6.0 run. Nothing is removed from the checks.
- **QG-07 Bundled ffmpeg checks** (2.0.2): the ffmpeg integration tests, the frame and LUT filters, the 360 marker and camera, and the Clean audio and MP3 output run on the bundled ffmpeg 9.x build.
- **QG-08 Pinned test ffmpeg** (2.0.2): the test job uses the bundled ffmpeg version, so results do not change with the runner's packages.
- **QG-09 Tests independent of machine load** (2.0.2): the preview frame test, the interface timing tests and the hardware probe tests pass on a busy machine without changing the product limits (REQ-061, REQ-104).
- **QG-10 Checks in automatic builds** (2.0.2): the notices check (`scripts/notices.sh --check`) has its exit code recorded; cargo-about is installed by a verified method; the installer configuration check (`scripts/package.sh <target> --config-only` and the Linux AppImage from stub binaries) runs on every push; there is no `.deb` package.

## Key decisions
- Detection runs inside videolore at first start on every operating system; installers do no tuning. One way of working everywhere, and it can be tested.
- One plain "How hard videolore works" choice instead of thread or process numbers; technical values stay out of the main part of Settings.
- Settings is a window inside videolore; it does not change the window layout (REQ-024). The setup notice closes by itself; there is no wizard.
- When the computer changes, custom settings win over the recommendation.
- Balanced behaves exactly like 0.2.2. Light limits each background job to half the cores; two jobs together can still use all cores, and preview playback is never limited.
- Exports made at different "How hard" levels may differ by a few bytes but look the same and have the same length. Preview quality never changes the export.
- Speech levels: Fast = the 0.2.x file (about 32 MB); Balanced about 190 MB; Most accurate about 574 MB; all MIT-licensed. Most accurate is recommended on at least 12 logical cores and about 16 GB of memory, Balanced on at least 4 cores and about 8 GB.
- Older processors get a clear message, not a slower fallback engine (dropped by Andrea for 0.4.0; it can be reconsidered on request).
- Hardware video encoding for export is built for every vendor with an automatic fallback and an output check; verified by hand (QG-05, see [Export](business-export.md)).
- Temporary files live in videolore's own private cache folder, not the system temporary folder.
- (2.0.1) The module-cycle reorganisation is internal: no file format, setting, file name or output changes (REQ-151 to REQ-153).

## Known limitations
- Speed and memory of the larger speech files, and their recommendation thresholds, are estimates (assumption).
- On virtual machines or containers whose core count changes between starts, each start may count as a new computer; with custom settings this only shows a notice.
- Processors without AVX2 cannot generate subtitles automatically; lines can be added by hand. No fallback engine is planned.
- Faster export limits (drivers, several graphics cards) are in [Export](business-export.md).

## Out of scope
- Detection or benchmarks in installers; long benchmarks; online databases of computers; telemetry.
- Speech files other than the three offered; translation.
- Graphics-card acceleration for effects and subtitles (export uses it; preview decoding and AV1 or VP9 hardware are in [Faster hardware export](business-hardware-export.md)).
- A slower fallback speech engine; performance settings per project; raw technical values in the main part of Settings.
