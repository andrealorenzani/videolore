# Business — Subtitle files and fonts (2.0.4)

Back to the [index](business.md). Batch 5 of the [roadmap tasks](roadmap_tasks.md), built in the 2.0.4 development.

## Requirements
- REQ-180 (implemented): File > Export subtitles… (renamed from "Export subtitles (.srt)…") offers .srt, .vtt and .ass. WebVTT writes the same cues as REQ-088 with a `WEBVTT` header, times `HH:MM:SS.mmm`, UTF-8 without byte-order mark. Acceptance: 3 lines give a .vtt that a reference WebVTT reader reads as 3 cues with the same times and text as the .srt; a cancelled write leaves no file; the command is greyed out with 0 lines (REQ-088).
- REQ-181 (implemented): The .ass export writes every line with the project's style and with the line's own place (REQ-089) and size (REQ-097) as ASS position and font scale. Acceptance: a line whose centre is at 10% across and 10% down is written at that point within 1% of the frame; a line at 150% size is written at 150% of the style size; a reference ASS reader reads all lines.
- REQ-182 (implemented): The Export dialog's Full video mode gets **Subtitles**: "Burned into the picture" (default, as in 2.0.3) or "Separate switchable track". A separate track is a subtitle stream: MP4 and MOV get a timed-text track, MKV gets an SRT-based track; it is named with the project language and is not switched on by default (built: its default flag is cleared, `-disposition:s:0 0`). The picture then has no burned text. Acceptance: with lines and "Separate track", ffprobe lists one subtitle stream with the language; the picture at a line's time has no text; the default output is unchanged from 2.0.3; a player can switch the track off (manual check, see [verification](business-verification.md)).
- REQ-183 (implemented): **Import subtitles…** (File menu and a button in the Subtitles popup) imports the lines of a .srt or .vtt file to the clip's range or to the whole video, as REQ-085 scopes subtitles. Built: the lines replace the lines already in that range, as a creation does (the REQ-044 question first when hand-edited lines would be replaced). The file's times are used as they are unless REQ-184 applies. The text is read as UTF-8 (a byte-order mark is accepted); another encoding is refused with a message. Styling tags are removed as in REQ-087; VTT positions are ignored. Lines already in the range follow REQ-044. One undo step. Acceptance: a 3-cue SRT gives 3 lines with the same times and text; a VTT with position settings gives plain text; a Latin-1 file is refused and nothing changes; one undo removes the import.
- REQ-184 (implemented): **Re-time from the speech** is a checkbox of the import dialog, off by default. When on, each imported line's start and end move to its first and last recognised word, matched with the rules of REQ-095 within the cue's time plus or minus 1 s; the consent and progress of REQ-014 apply. A line without a match keeps the file's times and the status line says how many. Acceptance: with simulated recognition a cue written 0.6 s early gets the recognised start; with the checkbox off the times are exactly the file's; Cancel changes nothing.
- REQ-185 (implemented): When a video with a `.srt` or `.vtt` file of the same base name in the same folder is in the media list, its clip's Subtitles popup shows "Import <file name>". Nothing is imported without a click. Acceptance: video.mp4 with video.srt beside it shows the offer; no line appears without the click; without a file there is no offer.
- REQ-186 (implemented): When a project opens, a media file whose size or modification time differs from its last analysis is analysed again: its subtitle-track list is updated and the status line names the changed files. Unchanged media is not analysed again (this extends the 1.2.0 rule that only media with unknown tracks is checked). Acceptance: an MKV replaced on disk with another subtitle track shows the new list after opening and is named in the status line; for unchanged media the analysis count is zero.
- REQ-187 (implemented): The bundled subtitle fonts cover Latin, Greek and Cyrillic (as now) and also Arabic and Devanagari (Hindi), so their subtitles show glyphs, not empty boxes, on every computer. No CJK font is bundled: Chinese, Japanese and Korean subtitles use the fonts installed on the computer. Where no installed font covers the script of a text, the subtitle popup and the export report it with a note, and some characters may show as empty boxes. Each bundled font is under the SIL Open Font Licence or the MIT licence and is listed in the third-party notices (REQ-031). The added fonts add at most 25 MB to each installer. Acceptance: a test line in Arabic and in Devanagari renders its glyphs in the export (compared with a reference render); a Japanese line on a computer with a CJK font renders its glyphs; on a computer without one the note appears; the notices list each font with its licence; the installer configuration check reports the size.
- REQ-188 (implemented): The subtitle editor (the Subtitles popup list and the line popups) shows text in every supported script with the bundled fonts or, for CJK, the installed fonts, so a Chinese, Japanese, Korean, Arabic or Hindi line can be read and edited; the note of REQ-187 appears when no font covers the script. Acceptance: a UI test shows a line in each script with its glyphs in the popup list, or with the note when no font covers it.

## Key decisions (2.0.4)
- [MINOR] .vtt and .ass are written from the same lines and times as .srt (REQ-088 rules), so every format shows the same text.
- [MINOR] Import is always a user action; no sidecar file is imported by itself, because a file the user did not ask for must not change the subtitles.
- [MINOR] A switchable track is an option; burned-in subtitles stay the default, so the picture looks the same in every player.
- [MINOR] Scripts outside the bundled list (CJK, Thai, Bengali and others) use the system fonts; the note of REQ-187 says when none covers the text. Decided by Andrea (2.0.4): no bundled CJK font, system fonts only (decision D61).

## Known limitations (2.0.4)
- Chinese, Japanese and Korean subtitles depend on the fonts installed on the computer: a computer without a CJK font shows empty boxes for those characters, and the program says so with the note of REQ-187. The exported video then looks different on each computer.

## Out of scope (2.0.4)
- Text read from picture-based tracks (DVD, Blu-ray, DVB) with OCR: not decided, stays on the roadmap.
- A style per line or per clip; translation.
