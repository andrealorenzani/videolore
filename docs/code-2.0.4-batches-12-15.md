# Code — 2.0.4, batches 12 to 15 (interface, player, 360 video, effects, quality)

Stages 8 to 12 of the 2.0.4 development. What is built and what was cut back is listed per stage; the plan is in [architecture-2.0.4-overview.md](architecture-2.0.4-overview.md).

## Stage 8 — interface (REQ-234 to 247)

- **Settings model.** `src/settings/interface.rs` (`Interface`): window, popup places, hidden/collapsed/flipped sections, workspaces (at most 10, names of 1 to 40 characters), toolbar list, shortcuts, theme, text size. Read leniently (`Interface::from_value`): every wrong value is dropped alone. Part of `Settings.interface`.
- **Window and popups (REQ-234 to 236).** `ui/place.rs`: `window_to_save` / `viewport_of` (the window is saved 0.5 s after it stops changing, restored by `native_options_for`; a place far outside the screens is replaced by the system's at the first frame), `saved` (a remembered popup place only when it is on the screen), `default_place` and `fit_width` (in a window of at least 1280x800 a popup goes in the column right of the timeline or above it, never over it).
- **Sections (REQ-237 to 239).** `ui/layout.rs` `arrange` + `Arrangement` (hide, collapse to a 120 px column, dock on the other side); header buttons in `ui/mod.rs` (`section_menu`); `ui/view_menu.rs` (Sections, Workspaces, Theme, Customise toolbar); commands in `app/dispatch_interface.rs`. Reset layout clears all of it.
- **Toolbar (REQ-240, 241).** `toolbar::fixed` is the user's list or the default 12; icon-only by default; every button has its command's name for screen readers (`widget_info`).
- **Shortcuts (REQ-242).** `ui/keymap.rs`: overrides are stored in the settings as "Cmd+Shift+B"; `install` makes them current each frame; `capture` takes the next key, reports a conflict (`RebindConflict`) or applies it. The Shortcuts popup has a Change button per row and Reset shortcuts.
- **Theme and text size (REQ-243, 244).** `ui/theme.rs` (explicit text colours, contrast test ≥ 4.5:1, System follows egui's system theme; text sizes scale the text styles, not the zoom). The choices are in View > Theme and Settings > Appearance and start-up.
- **Text table (REQ-245).** `ui/strings.rs`: `Key` + English table + `tr!(Name)`; a test scans `src/ui/*.rs` for texts written directly in label, button, menu and tooltip calls. Add a key with a new variant at the end of both lists.
- **Accessibility (REQ-246).** eframe `accesskit` feature on (editor and player); tests read the accessibility tree.
- **Edit menu (REQ-247).** Clipboard, History, Clip, Subtitles submenus and Settings… (5 entries).

## Stage 10 — 360 video (REQ-261 to 267, 269 to 272)

- **Marker (REQ-261, 262).** `spherical::mark_matroska_with`: ffmpeg writes padding (a Void element) before the Info element; the Projection element grows the Tracks element and the padding shrinks by the same bytes, so nothing after Tracks moves and only the SeekHead entries of the moved elements change (same byte count). Done in place. `mark_equirectangular_with` and the Matroska writer carry the source's initial view; the export gives them the first 360 source's `format.pose`.
- **Initial view (REQ-269).** `media::spherical_pose` (ffprobe side data, range checked) and `spherical::read_pose` (Spherical V1 XML of MP4/MOV, which ffprobe does not report); `camera::start_camera`; `render/segments.rs:start_path` puts the pose as the first point of the path when the user has none at 0.
- **Mark (REQ-263).** `MediaFormat.marked_360` (only a 2:1 picture); Clip details checkbox, `SetMarked360` (not an undo step: media data).
- **Presets and note (REQ-264, 265).** `choice::video_field_reason`, `choice::sphere_frame_note`; the 360 plan drops frame effects (`plan.rs`).
- **Speed and drag (REQ-266, 267).** `camera::command_lines_capped` with `GraphSpec.camera_updates` (10 in an export, 0 in the preview); `Preview.draft` halves the still while a camera change is live, back after `CAMERA_RESTART`.
- **Camera model (REQ-270, 271).** `Camera.roll_cd`, `Ease`, Shift+drag (`RollCamera`), Roll and "Ease in and out" in the POV popup; roll checked on the real `v360`.
- **Keyboard (REQ-272).** The picture takes the focus on a click (`keyboard_camera_id` tells `keymap::collect` to leave the arrows): arrows turn 5°, Page Up/Down zoom, Enter makes a POV.

## Stage 13 — speed, pictures, 360 text and paths (REQ-281, 287, 257 to 260, 268)

- **Speed (281).** `Clip.speed` in thousandths (500 to 2000, saved only when not 1000). `Clip::len()` is the length **on the timeline** (source length divided by the speed); `src_len()` is the source part; `to_timeline`, `to_src` and `src_at(offset)` convert. Keyframes stay in source time and `Clip::keys_to_timeline` puts them on the timeline's clock for the picture effects; subtitle lines map with `to_timeline`; the volume keys stay in the clip's timeline time. `Segment.speed` with `src_from`, `src_to`, `rendered_src` and `lead_src`; the graph uses `setpts=(PTS-STARTPTS)*1000/speed` for the picture and one `atempo` for the sound; `camera::command_lines_speed` times the 360 camera commands on the output clock. A clip with a speed is never stream copied, and two clips with different speeds cannot be merged (`DIFFERENT_SPEEDS`). Clip details has a Speed field (`Command::SetSpeed`).
- **Picture items (287).** A picture item is a `TextItem` with `picture: Option<Box<Picture>>` (`src/picture.rs`: PNG size from the header, the image fitted in the box and centred on the place). So the lane, the box in the preview, move, resize, align and undo are the text item's; its text is the file name. It makes no ASS events: `render::picture_overlays` gives `PicOverlay`s and `build_graph_pics` adds a looped still input (`-loop 1`, `Input.still`) and an `overlay` with `enable='between(t,..)'` before the subtitles. A missing file stops an export (`RenderError::Picture`) and is skipped in a preview; the 360 video export and text effects do not apply to pictures. `Command::AddPicture`, `Dialogs::pick_picture`, the Add Picture row and `Action::AddPicture`.
- **360 text (257 to 260).** An anchored line is drawn as a text item with the preset's outline or box (`segments::anchored_line_items`); the word highlight is karaoke (`TextItem.karaoke`, never saved, `ass::highlight_chunks`). Generated lines on a 360 source are anchored at the view's centre (`AppState::generation_anchors`, used in `finish_create`). `Command::ReAnchor` moves the anchor of the selected lines and texts to the view; `ui/placement.rs:off_view_arrow` and `ui/picture.rs:off_view_arrows` draw the arrows (a click sends `TurnCamera` with the turn).
- **Camera paths per clip (268).** `CameraPaths.clips` holds a clip's own path; a clip without one follows its source's until its path is first changed (copy on write, `set_in_clip`, `edit_in_clip`, `remove_in_clip`). `AppState::clip_for` finds the clip a POV time belongs to. A copied, pasted (`clipboard_camera`) or split clip gets a copy. Saved as entries with a `clip` field; entries of clips that are not there are dropped on opening.

## Stage 14 — spatial sound, picture subtitles, quality items (REQ-273, 253, QG-14 to 18)

- **Spatial sound (273).** `src/spatial.rs`: a 360 clip with a 360 picture and four audio channels is read as first-order ambisonics (ACN order W, Y, Z, X; this is an assumption, no other four-channel layout is checked). `rotate` turns the field by the camera's yaw and pitch, `cardioid_pair` reduces it to stereo (`0.5 * (W +- Y)`: two cardioid microphones at 90 degrees to each side), `Rotator` reads the camera path (`camera::at`, source time) every 10 ms and interpolates the angles inside a block, so a camera move makes no clicks. Roll is not applied; pitch changes X and Z only, so it does not change the pair (kept in `rotate` and tested). A **pre-pass** (`spatial::prepare`) starts ffmpeg through the `Runner` (four channels, 48 kHz, raw float on a pipe), rotates block by block and writes a 32-bit float stereo WAV `spatial-<hash>.wav` in the work folder (private, `.part` then rename; the name hashes the file, range and camera path, so a file found is the right one; cancel and failure leave nothing). `Segment.spatial` (set in `segments()` from the clip's own file, never a preview copy) makes the graph read the WAV as one more input after the pictures (`Graph.spatial` lists the jobs) instead of the clip's sound; the picture still comes from the clip. Export: `export::prepare_spatial` after the work folder is made (also for Only audio); the 360 video export clears it (the sound stays as recorded). Preview: `Preview::prepare_spatial` runs it synchronously before the audio process starts and the wall clock of that run starts after it (`Preview.prepass`); it removes the files of earlier camera paths, and a clip longer than 10 minutes keeps its recorded sound in the preview. Measured (test profile, debug build): 120 s of 4-channel sound in 1.7 s, 69 times real time (`the_pre_pass_runs_far_faster_than_real_time` prints it); a one-minute clip waits about 1 s before the first sound in the preview.
- **Picture subtitles in the player (253).** `MediaFormat.picture_tracks` (`media::PictureTrack`: ordinal among all subtitle streams, kind `pgs`/`dvd`/`dvb`, language, title; read by `picture_tracks`, sanitised on project load). `Project.picture_sub` (media and ordinal, never saved) is what the player has chosen; `segments()` copies it to `Segment.picture_sub` (not for a 360 clip) and the graph overlays the file's own subtitle stream on the picture before the trim: `[k:v:0][k:s:N]overlay=eof_action=pass:format=auto[psI]`, a `split` of the stream when several clips of the file use it, so the subtitles are scaled and fitted with the picture. Player: `Source::Picture`, listed after the text tracks and marked "(picture)" (`Source::menu_name`); choosing it sets `picture_sub` and clears the lines, any other choice clears it; there is nothing to drag. Limits: a subtitle already on screen when a run or a paused picture starts inside it appears at its next change (ffmpeg does not replay earlier display sets after a seek); no picture subtitles on a 360 clip. The test fixture is a PGS stream written by hand in `player/tests/ffmpeg.rs:pgs` (own work, GPL-3.0, no third-party file), muxed with the `sup` reader and checked at the pixels of the box before, inside and after its time.
- **Quality items.** QG-14: the speech tests use `tests/fixtures/align/speech.mkv`, so CI installs no speech synthesiser; the 360 test sphere is 1024 x 512; measured here: the cycle check runs in 1.7 s, the pinned ffmpeg and ffprobe are 173 MB each unpacked (the download size and the CI times are read on the first CI run). QG-15: pointer tests (colour picker and Export dropdowns in `ui/text_ux_tests.rs`, keyframe bar in `ui/clarity_ux_tests.rs`), golden arguments of formats 4 and 5 (`project-v4-1.2.6.vlproj`, `project-v5-1.3.0.vlproj`, `export-argv-v4-v5-in-2.0.4.txt`, recorded at 2.0.4 from hand-made projects, not by the old versions), and a large-picture memory test. QG-16: `text.rs` is split into `text/timing.rs`, `text/layout.rs`, `text/events.rs` (the types and `Texts` stay in `text.rs`, re-exported); one box rule, `placement::padded_line_rect`, used by the measured box (`placement::line_rect`) and the preview's hit boxes (`ui/placement.rs:line_box`), which now share `line_font` and `line_wrap`; the cycle check passes. QG-17: `build.rs` explains a missing splash summary, `scripts/version.sh set` runs the notices check afterwards as a reminder, the player's notice file has no version line (it names no version of its own), and each splash picture (88 KB) stays in the shared library (assumed: the linker drops the one a program does not use; not measured). QG-18: the four UI frame gates run as `sampled` (best of up to five runs, same limits), the probe fakes that answer have long limits (200 ms per try), and a test checks the notices for the bundled fonts and the font of the tests.
