# Code — 2.0.4, batches 5 to 7 (subtitle files, editing gestures, whole-video clarity)

The first four stages of the 2.0.4 development (stage 0: code split; stages 1 to 3: REQ-180 to REQ-205). Where each part is: [code-index.md](code-index.md) (sections "2.0.4"). The plan and the decisions: [architecture-2.0.4-overview.md](architecture-2.0.4-overview.md).

## Stage 0 — files split without a change of behaviour

- `src/render.rs` (3500 lines) is now a hub and five files in `src/render/`: `segments` (what each clip contributes), `inputs` (geometry, runs of one file, the music bed), `graph` (the one `filter_complex`), `plan` (stream copy or re-encode, the audio-only plan), `args` (export, preview, still and check argv, `FrameKey`); the tests are in `render/tests.rs` and `render/golden_tests.rs`. The submodules are private and `render` re-exports them with `pub use self::x::*`, so every item has one public path. The golden argv tests passed unchanged.
- `src/app.rs` keeps the state and the dispatcher; the arms of `dispatch_inner` are in `app/dispatch_{project,subtitles,settings,playback,view}.rs`. Each is a method that returns `Routed::Done(result)` or `Routed::Pass(command)` (the command is handed back unchanged for the next area); the arms keep their `?` and `return` because they run inside a closure. The small arms that call other `app/` files stay in `dispatch_inner`, which ends with "command not handled" for a command no area knows. `is_enabled` and `disabled_reason` are in `app/enabled.rs`, `tick` in `app/tick.rs`.

## Stage 1 — subtitle files and fonts (REQ-180 to 188), project format 11

- **Formats.** `srt::Format` is chosen by the extension of the file (`.vtt`, `.ass`, else `.srt`); `Command::ExportSrt` keeps its name. WebVTT writes the SRT cues under a `WEBVTT` header with a point before the milliseconds and `& < >` as entities. The `.ass` file is `ass::document` for the project's frame, so places and sizes are the ones of the export.
- **Separate track.** `FormatChoice.subtitles` (`SubtitleMode`) goes into `plan_export_choice`: with `Separate` the plan carries a `SubtitleTrack` (SRT, or WebVTT for WebM) written into the private work folder as a third input; the argv adds `-c:s mov_text|srt|webvtt`, `-metadata:s:s:0 language=<iso 639-2>` and `-disposition:s:0 0`. The lines are left out of `subs.ass` (texts and lines fixed to the sphere stay burned). A separate track forces a re-encode, like a burned subtitle does. ffmpeg's MP4 writer marks the first track of each kind enabled whatever `-disposition` says, so `mp4tracks::disable_subtitle_tracks` clears that bit of the subtitle track (one byte, in place, before the file is published); Matroska takes the disposition as it is.
- **Import.** The file is read when the dialog opens (`srt::read_file`: at most 16 MiB, UTF-8 with or without a byte-order mark, anything else refused with a message). The target is the clip's source range, or every part of the file's source that the timeline uses; the lines replace those of the range as a creation does (`replace_range`), in one undo step ("Import subtitles"). The dialog warns when hand-edited lines would be replaced. With "Re-time from the speech" the import goes through the creation machinery (`CreateRequest.import`, `stt::Mode::Retime`, the consent and the progress of a creation); `align::retime` moves each matched line to its first and last found word, an unmatched line keeps the file's times and is counted in the status line. The same-name file of a video (`subs_import::sibling_file`) is looked for when the Subtitles popup opens, after an import and when a project opens; nothing is imported without a click.
- **Changed media.** `MediaItem.stat` (size and modification time of the last analysis, in the project since format 11). `find_changed_media` compares them with the disk when a project opens; a changed file is probed again by the track check (new `TrackCheck.probed`), its format replaces the old one, the project does not become unsaved, and the status line names the files. A file without recorded values (format 10) only records them.
- **Format 11.** One bump (`SCHEMA_VERSION` 11): `MediaEntry.file_size`, `modified_ms` (both optional). 2.0.3 refuses a format 11 file (`TooNew`). The cap stays 16 MiB until the stage that needs more.
- **Fonts.** Noto Sans Arabic Bold and Noto Sans Devanagari Bold are compiled in (`assets/fonts`, sha-256 and licence in `SOURCE.txt`, `packaging/notices/third-party.txt`). libass does not look into the fonts folder for a missing glyph, so `ass::escape_scripts` writes `{\fnNoto Sans Arabic}` around each Arabic run (and the Devanagari one) and `{\fnNoto Sans}` after it; `export::write_subtitles` copies the three faces. No CJK font is bundled: `fonts::coverage_of` reads the character maps of the installed faces (skrifa) on the font scan thread and `missing_note_in` gives the note "No installed font shows … text; install a font for it" for the subtitle list, the line popup and the Export dialog. The interface gets the faces as lowest-priority fallbacks (`ui::scripts::install_for`; for CJK the first installed face that covers the script, read once).

## Stage 2 — editing gestures, autosave and safety (REQ-189 to 199)

- **Autosave.** `autosave` writes `<cache>/autosave/<sha-256 prefix of the path>.vlproj` (+ `.path`; `session-<hex>` for a project never saved) from a clone of the project on a worker thread, at most every two minutes and only with unsaved changes. Save, Discard of the changes, closing and opening another project remove the copy of the open project. At start `find_recoveries` offers the copies newer than their project (or of a project never saved): Recover opens the copy as unsaved changes (the saved project stays the reference of the marker), Discard deletes it, Cancel leaves it. The copy is read with the strict project loader; the `.path` text is bounded and checked.
- **Gestures.** The UI keeps the drag in `UiCache` and sends one command on release: `TrimEdge` (whole frames, inside the source, at least one frame; no change, no undo step), `RetimeSubtitle` from `subtitles::dragged_edge` (steps of 0.1 s, never closer than 0.1 s), `MoveFade` (`Timeline::move_fade`; only a boundary without a fade takes it). `[` and `]` are the actions `PrevMarker` and `NextMarker` (`app/stops.rs`: fades, lines, texts, clips with their own effects). Delete with lines selected is `DeleteSubtitles`; `ShiftLines` moves them together by 0.5 s and stops at 0 s or the end of the file.
- **Paste.** Copy and Cut put a marker text on the system clipboard, and `Event::PasteImage` is bound to Paste, so the paste key reaches the program whatever the clipboard holds (egui sends nothing for an empty clipboard).
- **Undo and files.** `History::forget` drops the snapshots that refer to a removed file; the others stay in order.
- **Guides.** `placement::snap` (centre lines, thirds 33 % and 67 %, other boxes' centres, within 1 % of the picture); `snap_to_guides` and `show_safe_areas` are program settings (never in the project).

## Stage 3 — whole-video and keyframe clarity (REQ-200 to 205)

- The whole-video Scale or Move popup lists one row per clip that has its copy; the selected row (`Popups.copy`, `Command::SelectCopy`) is shown and edited through the clip's own commands; Remove effect still removes every copy.
- `app/offer.rs`: after Append, Paste or Split (`AppState::dispatch` compares the clips before and after) the effects that every other clip has and a new clip lacks are offered in the status bar; "Apply to new clips" copies them in one undo step.
- Keyframes: markers 12 px, pick within 8 px, typed time (`Command::MoveKey`), Left and Right when the bar has the focus (the focus lock filter keeps egui from moving the focus; `bar_focus_id` tells `keymap::collect` to leave the arrows), Copy keyframes and Paste keyframes to (`KeysClip`, in the clip's own time).
- **REQ-202 reading.** A clip has one Scale and one Move (its copy), so there is no separate whole-video value to draw. The second, dashed set of handles is the copy selected in the open whole-video popup when it belongs to another clip than the one under the playhead (shown at the same time into its clip); a drag changes only the copy its handle belongs to.
- A LUT chosen again for a clip that already uses that file changes nothing and says so.
