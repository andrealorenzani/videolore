## Stage 4 — faster hardware export (REQ-206 to 211)

- **Output check (REQ-206).** When the hardware file has the frame count the plan gives (`render::expected_frames`: every clip's length in whole frames; `outcheck::counts_match`, within one frame), the normal method's video graph is rendered only around the three samples: `outcheck::sample_ranges` gives one range of one second per sample group, `render::check_range_graph` builds the graph from the start of the range (only the clips that begin before its end are read), `outcheck::compare_range_args` runs it next to the hardware file read from the same place (`-ss`, `-t`) and cuts the graph at `RANGE_LEN` with `trim`. Each range has its own work folder (subtitles and camera files cut to the range). The graph of a clip whose length is not a whole number of frames gets a frame more from the rounding of `fps`, which shifts every later frame; then (and when a sample does not match) the old exact check runs: the whole graph once (`render::check_graph`, `compare_args`, `judge`). So the short check is an optimisation: a file that fails it is judged by the exact one, and a faulty file never passes.
- **Quieter check (REQ-208).** The check is a job that waits for an export or a subtitle job: `AppState::pause_or_resume_hw_probe` (called in `tick`) stops a running check and starts it again when the last job ends; `hw_paused` says it waits. One process at a time (the probe runs its candidates in sequence).
- **Busy or hanging (REQ-210).** The probe command prints its progress on stdout; `hwenc::timed_run` watches output and, through `Process::cpu_ms` (sysinfo, `machine::process_cpu_ms`), the processor time. Output, or 20 ms of processor time, is `Activity::Busy` (retry, REQ-061); neither is `Idle` (`Reason::Hanging`, skipped after its first try); no reading is `Unknown` (retry, as before). A process that is gone is not looked at.
- **Session memory (REQ-209).** A candidate that hangs, or runs out of time twice without being busy, is in `HwStatus.slow`; `AppState.hw_slow` keeps it for the session (never saved) and the next check passes it as `skip` (`Reason::SkippedSlow`, "skipped: too slow twice"). The automatic repeat of an inconclusive check, "Try video hardware again" and "Use recommended" try everything again.
- **Texts.** `ui::settings::INTEGRATED_NOTE` after the Faster explanation when a format would use integrated graphics (`Candidate::graphics`: Quick Sync and VideoToolbox are integrated, NVENC and AMF dedicated, a VA-API device by `/sys/class/drm/<node>/device/vendor`); `REPEATING` ("check inconclusive, repeating") while `AppState::hw_repeating`.

## Stage 5 — hardware reach (REQ-212 to 219)

- **AV1 and VP9.** `hwenc::Codec` has `Av1` and `Vp9` (no profile argument); the candidates are `<codec>_<vendor>` names found in `-encoders`. `format::VIDEO_PRESETS` has 21 entries: the twelve of before and, at the end, AV1 in MP4 (1080p25, 1080p30, 720p25, 4K25, 480p25) and VP9 in WebM (1080p25, 1080p30, 720p25, 480p25); `preset_settings` returns `None` when the encoder (libsvtav1 or libaom-av1, libvpx-vp9) or the container's audio encoder (libopus for WebM) is missing, so the preset is not listed. A preset has no bitrate; a hardware export of a preset aims at `hwenc::preset_bitrate` (8 Mb/s for H.264 1080p25 by pixels per second; HEVC 0.6, VP9 0.65, AV1 0.5). libvpx-vp9 gets `-crf 32 -b:v 0`.
- **Quick Sync constant quality (REQ-215).** `Candidate::constant_quality` also exists for Quick Sync; its arguments are `-global_quality <qp>` and no bitrate; the 1.5 times size guard and the coarser second run are the VA-API ones.
- **Hardware decoding (REQ-214).** `hwdec` (new module): `Decoder` (vendor, device) with `-hwaccel cuda|qsv|d3d11va|vaapi|videotoolbox` (and `-hwaccel_device` for VA-API), `probe` (a short clip made by the bundled software encoder of each format, decoded with each decoder; a decoder works when ffmpeg gives all 15 frames without a message about falling back), `apply` (puts the decoder before each input of a preview run by the file's format). The probe runs after the encoder probe in the same thread (`HwState.decoders`). `Preview::set_decoders` / `AppState::apply_hw_decoders` (only with Faster); a run that ends badly sends a sentinel on the error channel, `Preview::take_hw_fallback` makes `tick` start again at the playhead without decoders (the picture on screen stays, nothing is said). Preview copies (`ProxyTask.hwaccel`) retry once without when the run fails.
- **Graphics card (REQ-216).** The probe keeps every working candidate (`HwStatus.working`, best first, `devices()` by `Candidate::label`); `Settings.graphics_card` (`None` = Automatic; a short text without control characters) is only compared with those names (`HwStatus::chosen`); `Command::SetGraphicsCard` ignores a name that is not a working device; it also picks the decoder (`hwdec::choose`). Cleared when the machine changes.
- **Old libva (REQ-217).** `Platform.libva_version` is read from the file name of the library (`libva.so.2.2000.0` is 2.20); `HwStatus.libva_note` ("libva 2.20 … 2.21 or newer … normal method") is shown in Advanced.
- **360 and frame effects (REQ-218, 219)** need no new code: the check graph is the export graph (frame effects, anchored texts); the tests prove it with the real ffmpeg and a simulated hardware run.

## Stage 6 — export and preview speed (REQ-220 to 224)

- **Names (REQ-220).** `VideoPreset::label` shows the plain codec name; `tooltip` names the encoder.
- **Warning (REQ-221).** `frame::over_cap` (before the cap), `AppState::frame_over_cap(preset)`, `ui::export_dialog::over_cap_warning` under the video row.
- **Blurred fill size (REQ-222).** The fill is computed at an eighth of each side (`frame::BLUR_DIVISOR` 8; REQ-222 says a quarter). Measured with ffmpeg 9.0.2 on a 4K source in a 2160x3840 frame (8 s, 3 runs): divisor 8 took 2.9 to 3.1 s, divisor 4 took 3.3 to 3.7 s (1080p source in 1080x1920: 1.4 s against 1.5 to 1.6 s). Kept 8: cheaper, the 2.0.3 output stays, and each side is below the quarter the requirement names.
- **Kept background (REQ-223).** `render::Background` (`Normal`, `Only`, `Cached`) in `build_graph_bg`; `FrameKey::background_name` (a hash of source frame, frame size, shape and fit, Apply LUT; none for a colour fill, a 360 clip or a fade). The still thread (`preview::render_with_kept_background`) makes the background once into a raw RGBA file in the private still folder (`bg-<hash>.rgba`, one at a time), then draws the picture over it; a missing or failed file falls back to the whole render. `Preview::background_renders` and `still_renders` count them. Playback is not cached.
- **Queue (REQ-224).** Import analysis (`probe_pool`) and the subtitle track check run at `Priority::Background`, like preview copies and subtitle preparation; preview and export outrank the hardware check, which outranks them.

## Stage 7 — platforms and installers (REQ-225 to 233)

- **CI.** `.github/workflows/installer-config.yml` (reusable; also runs on pull requests that touch `scripts/package.sh`, `packaging/` or `assets/icon/`); `build.yml` calls it as job `package-config` and the executables and installers `needs` it; a step runs `cargo test … cpu_message` and fails when no test ran (REQ-227, test `app::settings_tests::cpu_message_is_shown_when_the_processor_features_are_forced_off`); `.github/workflows/advisories.yml` runs `cargo deny check advisories` every Monday (read-only).
- **Packaging.** `packaging/tools.lock` has `[nsis]` (3.09, SHA-256 of the zip cargo-packager downloads); `scripts/package.sh tool NAME` checks a pinned tool (`VIDEOLORE_TOOLS_LOCK` names another lock file, for the test) and the Windows branch checks NSIS before `cargo packager`. The licence file of the Windows installer is `dist/stage-…/third-party-licence.txt`, the notices with a UTF-8 byte-order mark (the file in the repository stays plain). The Linux archive has `<name>.sh` (`packaging/linux/launcher.sh`) and `<name>.desktop` (`launcher.desktop`, `Exec` finds its folder through `%k`); `--stub` builds the archive too, and the CI job lists it.
- **One window (REQ-230).** `instance` (Windows and Linux): lock `<cache>/instance/running.lock` (`File::try_lock`), heartbeat every 250 ms, `inbox/` for the second start's path; `desktop::take_open_requests` adds `instance::poll_current` (the first of several). `main.rs` calls `instance::start` before the window.
- **macOS menu (REQ-232).** `desktop::macos_menu` is the data (application menu: Hide, Hide Others, Show All; Window menu: Minimize, Zoom; no Quit and no Cmd+Q, so Cmd+Q reaches the program and its unsaved-changes prompt); `desktop::macos::install_menu` builds an `NSMenu` from it with `objc2-app-kit` when the application is about to finish launching (one more `unsafe` call, `initWithTitle:action:keyEquivalent:`, with a SAFETY comment, in the module that already allows it). Compiles for `aarch64-apple-darwin`; behaviour is a manual check (verification item 16).
- **Wayland drops (REQ-233).** No code: the dropped-files path is the X11 one, and File > Import media… and File > Open… stay.
