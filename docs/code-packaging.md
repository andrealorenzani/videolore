# Code — installers, notices and known limitations

## Release assets

Every release gets nine files: the five below for the editor and, since 1.6.0, the same four installers for videolore player
named `videolore-player-<ver>-...` (see [code-player.md](code-player.md)). Names are checked by a test against
`scripts/package.sh` and the workflow. The editor's files:

| File | Made by |
|---|---|
| `videolore-<ver>-windows-x86_64-setup.exe` | cargo-packager 0.11.8, NSIS, per-user install (no admin), Start-menu entry, uninstall from Apps settings, `.vlproj` association, licence page = notices |
| `videolore-<ver>-macos-aarch64.dmg` | cargo-packager (`.app` with `.vlproj` document type), ad-hoc `codesign --force --deep -s -`, then `hdiutil` (drag to Applications) |
| `videolore-<ver>-linux-x86_64.AppImage` | Hand-built AppDir + appimagetool 1.9.1 with the pinned static type2 runtime (needs `fusermount3`, not libfuse2) |
| `videolore-<ver>-linux-x86_64.tar.gz` | `tar`: folder with `videolore` (0755), `ffmpeg`, `ffprobe`, `fonts/`, `notices/`, `videolore.png`, `README.txt`, marker `.videolore-bundle` |
| `videolore-<ver>-third-party-source.tar.xz` | FFmpeg sources of the bundled builds, the build scripts at the pinned commits, font reference and licence, README |

The installers are not code-signed (Gatekeeper / SmartScreen show a warning the first time).

### cargo-packager configuration (Windows and macOS)

`scripts/package.sh` writes `dist/stage-<target>/Packager.toml` and runs
`cargo packager --release --config` on it. Rules for that file (cargo-packager 0.11.8 rejects
unknown keys and wrong enum spellings):

- Every path is absolute: cargo-packager reads relative paths from the folder of the
  configuration file, not from the repository. Under Git Bash on Windows the paths are written
  as `D:/...` (`cygpath -m`).
- `name = "videolore"` must be present; without it cargo-packager stops with "Not a directory".
- Enum values are camelCase: `role = "editor"`, `installMode = "currentUser"` (the NSIS key is
  `installMode`; `install-mode` is not accepted).

`scripts/package.sh windows-x86_64 --config-only` (or `macos-aarch64`) only writes the
configuration, with no ffmpeg and no build. A unit test
(`packager_config_is_valid_for_cargo_packager` in `src/packaging.rs`) generates both and checks keys, enum values and
paths. To check a configuration with the real tool on Linux, stage stub files in
`dist/stage-<target>/bin` and `res/` and run `cargo packager --config <file> -f app`
(it also builds on Linux; `-f nsis` needs `makensis`). There is no `.deb` package.

`scripts/package.sh linux-x86_64 [player] --stub` (2.0.2, QG-10) builds the AppImage from stub
programs (empty shell scripts for the executable, `ffmpeg` and `ffprobe`) with the pinned
appimagetool and its runtime, in `dist/stub/`; it skips the ffmpeg download, the smoke test,
the glibc check and the tar.gz. The CI job `package-config` runs it, with `--config-only` for
Windows and macOS, on every push and pull request, and checks the files of the AppDir.

## Bundled ffmpeg

- Pinned in `packaging/ffmpeg.lock` (URL + SHA-256 per platform, version, licence, build-script
  commit, source): BtbN `linux64-gpl` (static) and `win64-gpl-shared`, Martin Riedl's macOS arm64
  release build. Refresh the pins on every release; a vanished URL makes CI fail loudly.
- `scripts/fetch-ffmpeg.sh <target> <dir>` downloads, checks the SHA-256 and extracts only
  `ffmpeg`, `ffprobe` (and the DLLs on Windows).
- `scripts/package.sh` refuses a copy without the encoders libx264, libx265, libvpx-vp9, libopus,
  the video hardware encoders of its system (Linux: `h264/hevc_nvenc`, `_qsv`, `_vaapi`; Windows:
  `_nvenc`, `_qsv`, `_amf`; macOS: `_videotoolbox`) and the filters subtitles, amix, alimiter,
  psnr; the Linux copy must be dynamically linked (the hardware libraries libva, libcuda and
  libvpl are loaded from the system at run time).
- Location: next to the executable (Windows install folder, `Contents/MacOS` on macOS,
  `usr/bin` in the AppImage, the tar.gz folder).

## Notices

- `packaging/notices/third-party.txt`: components, licences, sources, written offer, H.264/HEVC
  patent note (shown in the About screen and the Windows installer).
- `packaging/notices/rust-crates.txt`: generated by `scripts/notices.sh` (cargo-about with
  `about.toml` / `about.hbs`); regenerate after any dependency change, CI checks it.
- `deny.toml`: licence allow-list, advisories, sources (cargo-deny).
- `assets/fonts/`: Noto Sans Bold 2.015 with `OFL.txt` and `SOURCE.txt` (URL and SHA-256).
- `assets/icon/videolore.svg`: the icon; `scripts/icons.sh` regenerates `icon.png`,
  `icon-256.png`, `icon.ico`, `icon.icns` and `icon-256.rgba` (the window icon, embedded).

## Desktop integration

- **Windows / macOS:** the installer registers `.vlproj`. A double-clicked project is passed as
  the first argument (Windows) or as an Apple Event (macOS, handled by `desktop::macos`).
- **Linux:** at start-up the AppImage (`$APPIMAGE`) or the tar.gz copy (marker file) writes
  `~/.local/share/applications/videolore.desktop`, the 256 px icon and the `*.vlproj` MIME type,
  and refreshes them when the file was moved; source builds do nothing. "Remove from application
  menu" in the About screen deletes them.
- On Windows and Linux a project double-clicked while videolore runs opens in a second window;
  on macOS it reaches the running window and asks about unsaved changes.

## Manual checklist per OS (before publishing a release)

Things CI cannot check. For each of Windows 11, macOS (Apple Silicon), Ubuntu LTS and Fedora:

1. Download the installer from the release page; install it by double-click (Windows wizard
   without admin rights; drag to Applications on macOS; on Linux mark the AppImage executable,
   or extract the tar.gz).
2. First launch: confirm the SmartScreen ("More info → Run anyway") or Gatekeeper ("Open
   Anyway" in Privacy & Security) step works as the README describes; the window opens in about
   a second and "checking ffmpeg…" disappears without an ffmpeg installed on the machine.
3. Import a video, play it, export it (H.264 and, with an HEVC source, HEVC that plays in
   QuickTime/Photos). With Export = Faster, run the QG-05 checklist of
   [code-hardware-qg05.md](code-hardware-qg05.md) on the machines that have the hardware.
4. Generate subtitles: the consent dialog appears, the download works, subtitles are shown in
   the preview and burned into the export.
5. Save a project, close and double-click the `.vlproj`: videolore opens it. With videolore
   already running: a second window on Windows/Linux; on macOS the same window, with the
   unsaved-changes question when needed.
6. The menu entry / Start-menu entry has the icon (Linux: after the first start).
7. Close the window and quit with Cmd/Ctrl+Q with unsaved changes: the question appears.
8. Uninstall (Windows Apps settings; delete the app on macOS; "Remove from application menu" and
   delete the file on Linux): the projects are still there.

## Known limitations

- Installers are not code-signed: a one-time confirmation is needed on first launch.
- Subtitle text in scripts other than Latin, Greek and Cyrillic falls back to the system fonts in
  the export (it can differ per OS or show boxes) and may not be readable in the app's editor.
- Removing a file from the media list also drops the undo history when an undo step refers to it.
- On macOS the standard application menu (Hide, Minimize) is switched off so that Cmd+Q can ask
  about unsaved changes.
- The proxy cache is never cleaned automatically; "Clear preview copies" empties it.
- Subtitle generation on x86-64 needs a CPU with AVX2, FMA and F16C (2013 or newer); on an older
  processor "Generate subtitles" shows a message instead (lines can still be added by hand). There
  is no slower fallback engine (not planned).
- Hardware video encoding ("Export: Faster") depends on the graphics driver; see the known
  limitations in [code-hardware.md](code-hardware.md).
- Speech is transcribed in 120-second chunks; a word cut at a chunk boundary can be lost.
- Some Linux file managers do not start a program from the tar.gz folder on double-click (see
  its `README.txt`).
- While an export and playback run together, other ffmpeg work (analysis, proxies) waits.
