## Decisions (ADR)
- ADR-105 Products and layout (TECHNICAL). Cargo workspace: root package `videolore` (lib + editor bin, unchanged) + member `player/` = package `videolore-player` (bin `videolore-player`). `[workspace] members=["player"], default-members=["."], resolver="3"`. Player depends on the lib with `default-features=false, features=["audio"]` (no stt: no whisper-rs, no ureq, no cmake/libclang needed for the player build). Rejected: (a) second `[[bin]]` in the root package (player graph would include whisper and ureq; no-network rule not provable by the dependency graph); (b) extracting a `videolore-core` crate now (move of ~50k lines before a feature release; risk; deferred to Future work); (c) second repository (duplicated engine). Reason: the player's "no network, no speech" rule becomes a CI check on `cargo tree`.
- ADR-106 Player engine reuse (TECHNICAL). The player builds an in-memory one-clip `Project` (never saved) and drives the EXISTING `preview` engine, `render` graphs, `ass`, `camera` (drag + limits), `srt`, `placement`/`ui::boxes`, `media::probe`, `jobs` scheduler. No second ffmpeg command builder. Player state has no Save/Export/edit commands (structural: not in its command enum). Rejected: reuse the editor AppState with a mode flag (3515-line state carries save/edit commands; leak risk); duplicate graph code in the player (drift between preview and player).
- ADR-107 Player settings (TECHNICAL). No settings file in 1.6.0. Start: `machine::detect()` + `settings::recommend()` values in memory (Balanced, preview Automatic, no hardware export). Writes only the app cache (proxies) and private Work folders (scratch), never next to the video. No splash, no first-start notice. Consequence: no player preferences until a later version (Future work).
- ADR-108 Player packaging (TECHNICAL). `scripts/package.sh <target> [editor|player]` (default editor = unchanged CI call). Player: own Packager.toml (name `videolore-player`, product-name "videolore player", identifier `io.github.andrealorenzani.videolore-player`), no file association, no Linux desktop self-integration (tar.gz README says how to start), AppImage `.desktop` with Categories=AudioVideo;Player; no MimeType. Same pinned ffmpeg lock (second copy of ffmpeg/ffprobe inside the player installer; size cost, Q-D). Icon: the player uses the editor's icon artwork (Q-A closed 2026-11-19 = 1): same `assets/icon/*` inputs in Packager.toml, same window icon `icon-256.rgba`; no new icon file, no icons.sh change; the two installers differ only by name and identifier. Artifacts `videolore-player-${V}-<target>.{AppImage,tar.gz,dmg}` and `-setup.exe`. Rejected: player inside editor installer (D9), lighter custom ffmpeg (needs its own build pipeline; Future work).
- ADR-109 LUT parser (TECHNICAL). New pure `src/lut.rs`: `parse(&[u8]) -> Result<Lut, LutError>`; `.cube` only; keywords LUT_3D_SIZE / LUT_1D_SIZE / DOMAIN_MIN / DOMAIN_MAX / TITLE; comments `#`; file read with the existing read_limited pattern (16 MiB cap, regular file only); UTF-8 required; 3D size 2..=65; 1D size 2..=4096; exact entry count; each value finite (NaN/inf refused), clamped to [0,1]; DOMAIN other than 0..1 refused with message (Future work: support). Mixed kinds refused. A 1D LUT is converted to a 3D cube of size 33 by per-channel linear sampling (one code path, one ffmpeg filter). Rejected: ffmpeg reads the user's file (path enters a filter string; no validation before a long job; 1D/3D by extension is ambiguous); a `.cube` crate (unvetted parser on untrusted input for ~200 lines of code).
- ADR-110 LUT in the graph (TECHNICAL). Export/preview write the normalised 3D cube as `lut-whole.cube` / `lut-clip-<n>.cube` into the private Work folder (cwd; fixed names; never a user string in a filter). Filter: `format=gbrp,lut3d=file=<name>:interp=tetrahedral,format=yuv420p` (exact syntax verified by PE on the bundled build). Order per segment: picture scale (stage A/C, incl. per-frame Scale) -> LUT whole -> LUT clip -> overlay on background (stage C; the LUT is applied to the PICTURE branch before overlay so the background is untouched, D7) -> fades (stage D). Sphere360 segment: after v360, before the output. Subtitles and text: unchanged (after concat). Any LUT forces re-encode (REQ-023). Rejected: LUT on the concatenated output (breaks whole-then-clip order and paints the background; fades would be LUT-coloured black); LUT via sendcmd (no time dependence needed).
- ADR-111 LUT storage and format 8 (TECHNICAL). `Timeline.whole_lut: Option<String>`, `Timeline.clip_luts: Vec<ClipLut{clip: ClipId, path: String}>` sorted by clip id, empty entries removed, all `#[serde(default)]` (precedent ADR-093). Clip stays Copy+Eq. Path must be UTF-8 (chosen file names that are not UTF-8 are refused with a message). Split: both halves copy; merge needs equal LUT on both (like clean audio, "The clips have different colour effects"); remove clip drops entry. One undo per choose/remove/change. Schema 8 always written; 1.5.x refuse it with their newer-version message (file untouched). Load of 1-7 unchanged. Load validation: empty / over 4096 chars / NUL inside -> cleared with a note (ADR-104 precedent). Sha256 of validated LUT content kept in memory (sha2 crate, existing) for the preview key.
- ADR-112 Missing or changed LUT (TECHNICAL). Project open: missing file -> project opens, status names the file, LUT inactive in preview; export stops before anything is written with a message naming the file (REQ-136). Changed content: validated again at the next choose and at the next export start; the in-memory hash decides preview stills (a changed hash re-renders once). No silent partial output.
- ADR-113 Splash (TECHNICAL). `src/splash.rs` (pure): `layout(img:(w,h), screen:(w,h), min_gap) -> Layout{scale, image, popup}`; `fit_text(measure: Fn(size)->(w,h), rect, max_size)` binary search; `text_colour(rgba_rect_mean)`; `version_text(CARGO_PKG_VERSION)` -> "Version X.Y"; `summary()` = include_str!. Assets compiled in: `include_bytes!(concat!(env!("CARGO_MANIFEST_DIR"), "/assets/splash/", env!("CARGO_PKG_VERSION"), ".gif"))` and the same for `.txt` (missing file for the release = BUILD ERROR, which is the check the PM asked the Architect for). GIF decoded with `image` (gif feature, default-features off) on first show, UI thread, budget 100 ms; all frames kept as RGBA textures (one frame today ~1 MB); timed repaint only while the splash is open. UI: egui `Window` anchored centre, Order::Foreground, title bar with close control, inside `Popup::Splash` (AppState.popups) so Esc closes it through the existing rule; not an OS viewport (multi-viewport on Wayland/macOS untested). Scale: both parts scaled by min(1, avail_w/total, avail_h/506). Shown at editor start only; skipped whenever a project or video path is on the command line, including a double-click first start (Q-C closed 2026-11-19 = 1; no single-instance code). REQ-045 notice is queued (AppState.notice_after_splash) and shown after close.
- ADR-114 Icons (TECHNICAL). Phosphor Regular TTF (MIT; icons MIT; PE takes the file from the upstream Phosphor Icons release at one pinned version and records it, not verified by the architect) vendored as `assets/icons/Phosphor-Regular.ttf` + `assets/icons/LICENSE-Phosphor.txt` + `assets/icons/SOURCE.txt` (version, URL, SHA-256), like assets/fonts. Registered by `ui::icons::install(ctx)` as an extra fallback of egui's Proportional family (icons work inside any text, measurement included). Codepoints = named constants in `src/ui/icons.rs` (one per icon used). `ActionId` gets `icon` (required field of the ACTIONS table, single source for menus, toolbar, shortcuts). Greyed state: icon colour follows the text colour. Test: every constant exists in the font cmap (ttf-parser as dev-dependency; already in the tree via fontdb 0.24). Rejected: `egui-phosphor` 0.14 (egui 0.36 pin; no verified 0.37 release); `egui-pop-phosphor` (fork); SVG via egui_extras (resvg is MPL-2.0, outside the permissive list); Font Awesome (CC BY 4.0 needs attribution, REQ-143 forbids it); Lucide (ISC, valid alternative if Phosphor fails the audit).
- ADR-115 Notices (TECHNICAL). Two generated Rust notices: `packaging/notices/rust-crates.txt` (editor, unchanged name) and NEW `packaging/notices/rust-crates-player.txt` (`scripts/notices.sh --manifest player/Cargo.toml`); CI `--check` runs both. `third-party.txt` gains: Phosphor Icons (MIT, source, version), and an entry for the splash image (origin to be confirmed by Andrea, Q-E). `src/notices.rs` table gains the icon set and the image; About shows the same table in both programs. `stage_notices` copies the product's own Rust list.
- ADR-116 Versions (TECHNICAL). Root Cargo.toml and player/Cargo.toml both carry a literal version; `scripts/version.sh` writes both and the Cargo.lock entries of both packages, `check` compares all of them plus the README badge. `version.sh get` unchanged (root).
- ADR-117 Tests and gates (TECHNICAL). CI and scripts run with `--workspace` (fmt, clippy, test, llvm-cov). Coverage ignores `src/main\.rs$` and `player/src/main\.rs$`; line coverage 85% over the whole workspace. feature-coverage.sh scans `src tests player`. New CI step: `cargo tree -p videolore-player -e normal` must not contain `ureq` or `whisper-rs` (fail if found); `cargo deny --locked check` covers both packages. MSRV job: `cargo build --locked --workspace --all-targets`.
- ADR-118 Player open rules (TECHNICAL). Accepts one video path as argv[1] (Linux `Exec=videolore-player %f`, handy for tests) and File > Open (rfd) and drop (where winit delivers it). A `.vlproj` (extension, case-insensitive) is refused by extension WITHOUT reading the file. No file association, no odoc handler (macOS: no Apple Event code in the player).
- ADR-119 Player subtitles and camera (TECHNICAL). Embedded text tracks: the same extraction and conversion as the editor's "use the video's subtitles" (shared helper moved out of app/subs_create.rs into a non-app module; no copy). `.srt` read limited to 16 MiB, parsed by `srt::parse`. Positions: `subtitles::Pos` in the player state only (never written). Drag = `placement::boxes` + `ui::boxes` logic reused; on 360 the lines are fixed on the screen. 360 look-around = `camera::drag` + `camera::clamp` with the editor's live override (`preview` restarts from the playhead, latest-only, as today).

## Data flow (new)
- Start (editor): ... -> if no project argument: Popup::Splash open (decode GIF) -> status/notice queued until close.
- Apply LUT: Choose file -> read_limited -> lut::parse -> Ok: Timeline.set_lut(target, path) + in-memory hash, 1 undo; Err: message, nothing changed.
- Preview/export: render::segments() copies LUT paths and hashes -> build_graph writes the cube files into the Work folder (cwd) -> ffmpeg; the export re-reads and re-validates the file first (missing/broken -> stop before any output file).
- Player: argv/File>Open -> media::probe (jobs, Probe priority) -> one-clip Project in memory -> preview engine; subtitles from file/track in source time; camera override; full screen via ViewportCommand::Fullscreen.

## NFR (1.6.0)
- Splash: decode <= 100 ms on the reference machine (estimate, not a CI gate; CI test allows 1 s); no blocking of the window; memory about 1 MB per GIF frame.
- LUT: 1080p preview with a 33^3 LUT keeps the playback rate of the same clip without LUT within 20% (assumption, measured by PE with the 1.3.0 performance procedure); export with LUT at most 1.5x the same re-encode without (assumption, to measure); a 65^3 cube is about 6 MB of text in the Work folder, deleted with the folder.
- Binary/installer: font about 0.3 MB (to measure); player installer carries a second ffmpeg (size measured in CI, not promised).
- Player: starts with no settings file; window in < 1 s (as editor); no network code (CI check).
- Maintainability: new logic in new modules; app.rs and render.rs get wiring only.
- Portability unchanged: Windows x86_64, macOS 11+ arm64, Linux x86_64 glibc <= 2.39 (both products).
- Licences: every new crate MIT/Apache-2.0/BSD/ISC (cargo-deny); font MIT.

## Security (1.6.0)
- LUT is untrusted input: size cap 16 MiB, regular file only, UTF-8 only, token and count checks, no panics (property tests), validated bytes copied into the private Work folder under fixed names; no user string in any filter (ADR-110); missing or broken file stops export before output (ADR-112).
- Player: media is untrusted; same ffmpeg process model as the editor (child process, jobs queue, private folders); player never writes next to the video; `.vlproj` never read; no network (CI check on the graph).
- Splash/icons/summary: compiled in, no runtime file reads; `image` gif decoder used only on the bundled file.
- Supply chain: new direct crate `image` (gif) only; `ttf-parser` declared as dev-dependency; Phosphor font SHA-256 pinned in SOURCE.txt; cargo-deny and notices in CI.

## Risks (1.6.0)
- lut3d options/behaviour on the bundled 9.x build unverified (step 3). Colour matrix round trip yuv->rgb->yuv may move values by 1-2 levels: the export-vs-reference tolerance must allow it (test tolerance decided by PE, 2 levels per channel is the business target between preview and export, which share one graph).
- LUT performance on weak computers (estimate unknown).
- Splash summary file missing for a release = build error (intended); a stale summary is a process risk.
- Player scope creep; player duplicates ffmpeg (download size); player reuses the editor's preview engine, so an engine change affects both (tests in both).
- Phosphor icons: licence audit is by hand (MIT, font file from the project's release) — recorded in SOURCE.txt.
- The 1.5.x refusal of schema 8 is verified by hand only.
- Splash GIF static by decision (Q-B closed); origin of the image to be recorded in notices (Q-E, pre-release).
- Splash not shown with a path on the command line (Q-C closed): REQ-133 wording ("at every start") must carry this exception (PM flag).
