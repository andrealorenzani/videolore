# Business — Editing

Back to the [index](business.md).

## Features
- **Media list**: import video and audio files; each item shows "analysing" while it is inspected, then its name and duration, or a clear rejection. An **Add media** button sits under the list (2.3.0, same as File > Import media…). Importing never freezes the window.
- **Projects**: New, Open, Save and Save As; the window title shows the project name and a marker when there are unsaved changes; closing, quitting, opening or starting a new project with unsaved changes asks to Save, Discard or Cancel.
- **Timeline editing**: append, split, cut/copy/paste, merge, trim and reorder segments; the timeline closes gaps automatically. Undo/redo of at least 50 steps.
- **Fades through black**: between clips, and at the start and end of the video. Applied to one clip (both its edges) or to the whole video (a copy on each clip, see [Effects](business-effects.md)).
- **Preview**: play, pause and seek, with fades, music and subtitles visible. Video keeps playing in real time even if audio output stalls.
- **Preview copies**: very large sources get a smaller preview copy automatically, so the preview stays smooth; export always uses the originals. Controlled by "Preview quality" in Settings (see [Settings, performance and safety](business-performance.md)).
- **Window, recent projects**: see [Window, menus and effects](business-ui.md).

## Requirements

### Media and projects
- REQ-001 (implemented): Editing is non-destructive; source media files are never modified.
- REQ-002 (implemented): Media files (video and audio) can be imported into a media list showing name and duration; unsupported files are rejected with a clear message. Audio-only files are accepted into the list and can be placed on the music track (not on the video track).
- REQ-003 (implemented): A project can be saved and reopened; missing source files are reported by file name and the project still opens.
- REQ-004 (implemented): Undo and redo support at least 50 steps.
- REQ-026 (implemented): Save writes the current project file; Save As asks for a path; Save on a project never saved before behaves as Save As. Acceptance: Save As `a.vlproj`, edit, Save — `a.vlproj` is updated with no dialog.
- REQ-027 (implemented): The window title shows the project name and an unsaved-changes marker; saving clears the marker, and undoing back to the saved state also clears it.
- REQ-028 (implemented): New, Open, closing the window or quitting with unsaved changes asks Save / Discard / Cancel. Save saves and then continues (a failed save or a cancelled Save As stops the action); Discard continues without saving; Cancel returns to the editor unchanged. No prompt appears when there are no unsaved changes.
- REQ-029 (implemented): Projects created with 0.1.x open in 0.2.0 and produce the same result; project files from a newer version are refused with a clear message and left untouched.
- REQ-094 (implemented): Projects from 1.1 and earlier open in 1.2.0 with the same result: their fades between clips are kept, there are no start or end fades, every clip volume is 100% and every subtitle line is at its style's usual place. Projects saved by 1.2.0 also store start and end fades, clip volumes and subtitle line positions; older versions refuse them with their "newer version" message and leave the file untouched (REQ-029). Acceptance: 0.1 and 1.1 example projects render and export as before; a 1.2.0 file is refused by the previous version's check; damaged or hostile values in the new fields (position outside the picture, volume above 100%, unknown references) are refused or corrected without a crash (REQ-057).
- REQ-105 (implemented): Projects from 1.2.5 and earlier open in 1.2.6 with the same result (no 360 clips, every subtitle line at 100% size). Projects saved by 1.2.6 also store the subtitle line sizes, the "360°" switch of each clip and the points of view (REQ-096 to REQ-104, see [Boxes on the picture and 360 video](business-picture.md)); older versions refuse them and leave the file untouched (REQ-029). Damaged or hostile values (size outside 25%-400%, angles or zoom out of range, more than 200 POVs, POV times outside the clip, unknown references) are refused or corrected without a crash (REQ-057). Acceptance: a 1.2.5 example project renders and exports as before; a 1.2.6 file is refused by the previous version's check; the hostile values give no crash.
- REQ-113 (implemented): Projects from 1.2.6 and earlier open in 1.3.0 with the same result (no text items, no 360 anchors). Projects saved by 1.3.0 also store the text items (their text, effects, times, boxes, colours and fonts) and the 360 anchors of text and subtitle lines (REQ-108 to REQ-112, see [Text](business-text.md) and [Boxes on the picture and 360 video](business-picture.md)); older versions refuse them and leave the file untouched (REQ-029). Damaged or hostile values (time to live below 0.1 s or above 24 hours, which is refused on opening; effect settings outside 0.1-5 s, text longer than the subtitle limit, directions or sizes out of range, unknown references) are refused or corrected without a crash (REQ-057). Acceptance: a 1.2.6 example project renders and exports as before; a 1.3.0 file is refused by the 1.2.6 check; the hostile values give no crash.
- REQ-123 (implemented): Projects from 1.3.0 and earlier open in 1.4.0 with the same result, with two exceptions. (a) The "360°" switch of Clip details is removed: the switch of each clip is dropped and a clip is treated as 360 only from its file's spherical information (REQ-100). (b) A text item keeps its size: it gets the narrowest box width at which its text still has its old size, or the full picture width when none does. Projects saved by 1.4.0 also store the Clean audio marks of clips (REQ-114) and the width of text boxes (REQ-116); positions outside the picture are valid values (REQ-117). Older versions refuse them and leave the file untouched (REQ-029). Damaged or hostile values (text box width outside 10%–100% of the picture width, unknown references) are refused or corrected without a crash (REQ-057). Export choices (REQ-118 to REQ-122) are not stored in the project. Acceptance: a 1.3.0 example project renders and exports as before, except a clip whose switch was changed and a large multi-line text (exception b); a 1.4.0 file is refused by the 1.3.0 check; the hostile values give no crash.
- REQ-149 (implemented): Projects from 1.6.0 and earlier open in 1.6.1 with the same result for the clips they contain, with one exception (Q-F). A whole-video effect becomes the same effect on the clips that exist when the project opens (the whole-video fades become the first clip's start fade and the last clip's end fade), so no clip changes its picture or sound. **Exception (Q-F, Andrea, 2026-11-19)**, when a clip already has its own effect of the same kind: (a) Scale and Move: the clip and the whole video become one path on the clip. Scales are multiplied and moves added; the keyframes are the clip's start and end, the clip's own keyframes, and the whole-video keyframes shifted to clip time (only those inside the clip). The result is exact at these times and a straight line between them. At most 200 keyframes: the clip's own are kept first, then the shifted whole-video ones in time order. Combined scales stay within 10%-400%. A clip without its own Scale or Move gets the whole-video one unchanged (exact). (b) Apply LUT: the clip keeps its own LUT and the whole-video LUT is not applied to it; the other clips get the whole-video LUT (REQ-135). When a clip was combined or lost the whole-video LUT, the project opens with one status line saying how many clips were combined and how many kept their own LUT; no line when no clip changed; no undo step and no change mark. Projects saved by 1.6.1 are refused by 1.6.0 and earlier and left untouched (REQ-029). Damaged or hostile values are refused or corrected without a crash (REQ-057). Acceptance: a 1.6.0 example project with whole-video fades, volume and Scale renders and exports as before; a 1.6.1 file is refused by the 1.6.0 check; the hostile values give no crash. Conflict case: clip 1 (0 s to 4 s) has its own Scale 100% at 0 s and 200% at 4 s, and the whole video has Scale 100% at 0 s and 200% at 2 s. After opening, clip 1 is 100% at 0 s, 300% at 2 s and 400% at 4 s, 200% at 1 s (1.6.0 showed 187.5%; this is the approximation), and the status line says one clip was combined. Assumption: the conversion keeps the result for all other clips.
- REQ-324 (implemented): The Media section has an **Add media** button at its end, under the media list. It opens the same file dialog as File > Import media… (REQ-002) and adds the files to the list in the same way. The button is always shown, also when the list is empty (MINOR: same action, label chosen for the Media section). Acceptance: the button is the last item of the Media section; a click opens the dialog of File > Import media…; the chosen files appear in the list with their names and durations; the File menu entry still works.

### Timeline
- REQ-005 (implemented): A media item can be appended to the end of the timeline.
- REQ-006 (implemented): A segment can be split at the playhead.
- REQ-007 (implemented): Segments can be cut, copied and pasted; the timeline ripples so no gaps remain.
- REQ-008 (implemented): Contiguous segments from the same source with contiguous source ranges can be merged; the action is disabled otherwise. The clips must also have the same volume (REQ-084); otherwise Merge is greyed out with "The clips have different volumes".
- REQ-009 (implemented): A segment can be trimmed at either edge, within the bounds of its source.
- REQ-010 (implemented): Segments can be reordered; the timeline ripples.
- REQ-011 (implemented): A transition between clips is a fade-out followed by a fade-in through black, on video and audio, and can be removed; each fade lasts 0.5 s, or half the clip length for clips shorter than 1 s, so fades never overlap. Clicking a fade marker opens its settings, and a fade is removed from there or from the right-click menu (REQ-077). Fades in from black at the start of the video and out to black at its end, applied per clip or to the whole video (REQ-083), follow the same length rule.
- REQ-083 (implemented): Whole-video fades are copies of the first and last clip (REQ-147). Fade through black as an effect (REQ-082). **On a clip**: fades at both edges of the clip; at a boundary with a neighbour this is the REQ-011 fade-out + fade-in; if the clip is the first one, a fade in from black at its start; if it is the last one, a fade out to black at its end. **On the whole video**: the fade in from black goes to the first clip's start and the fade out to black goes to the last clip's end; each of these two is a copy that becomes an ordinary clip fade, editable in its clip's popup (REQ-147). Start and end fades belong to the clip they sit on: they move with it and are removed with it. Each fade lasts 0.5 s, or half the clip for clips shorter than 1 s, on picture and sound. Removing the effect from a clip removes the fades at both its edges. Each start, end and boundary fade has its own marker (REQ-077) and can be removed alone. The "Add fade" handle at boundaries stays. Acceptance: (a) with 3 clips, applying it to clip 2 gives fades at boundaries 1 and 2 and none at the start or end; (b) applying it to clip 1 gives a start fade and a fade at boundary 1; (c) applying it to the whole video gives a fade in at clip 1's start and a fade out at the last clip's end in preview and export, and no fade at other boundaries; after cutting the first clip, the new first clip has no start fade; (d) a 1.1 project shows exactly the same fades as before.
- REQ-012 (implemented): A zoom slider scales the timeline from showing the whole project to single-frame level. The slider is in the Timeline header, and View > Zoom in / Zoom out / Fit project (with shortcuts) also zoom.

### Preview
- REQ-013 (implemented): The preview supports play, pause and seek, and shows effects.
- REQ-034 (implemented): The still preview frame is re-rendered only when the picture at the playhead actually changes, and bursts of edits are combined. Acceptance: an edit that does not change the frame at the playhead causes no render; 10 rapid edits cause at most 1 render.
- REQ-035 (implemented): During playback, video continues in real time if audio output stalls; audio catches up or skips. Acceptance: with a simulated stall video time keeps advancing, and audio/video drift is at most 100 ms after audio resumes.
- REQ-144 (implemented): When playback is paused, or after a seek or an edit, the preview shows the picture at the playhead; it never stays black where the timeline has picture (fixes a black preview seen in 1.6.0 when paused). Acceptance: (a) play for 3 s, then pause: the preview shows the picture at the playhead, not black; (b) pause at 20 different positions, each reached by a seek, an edit or the end of playback, with and without effects: no black frame where there is picture; a fade through black still shows black at its own time.
- REQ-155 (implemented): The paused picture of the last ~20 ms of a clip is shown. Where the timeline has picture, the preview shows it when playback is paused, after a seek or after an edit, up to the clip's last frame, as REQ-144 requires. Acceptance: a 2 s clip at 25 fps paused at 1.98 s and at 1.995 s, reached by a seek and by an edit, shows its picture and not black, with and without effects; a fade through black still shows black at its own time.

### Responsiveness and performance
- REQ-032 (implemented): Importing never freezes the window: each item shows "analysing" and then its name and duration, or its rejection; several imports can run while the user keeps editing. Acceptance: importing 10 files does not block user input.
- REQ-033 (implemented): The number of ffmpeg/ffprobe processes running at the same time never exceeds the limit of the current "How hard videolore works" level (REQ-050; 3 for Light and Balanced, as in 0.2.x, and up to 6 for Maximum speed); extra work waits in a queue and requests that became obsolete (for example an older preview frame) are dropped. Acceptance: at every level, 20 imports plus an export plus preview never exceed the level's limit, and all jobs complete.
- REQ-038 (implemented): A source that is "big for this machine" gets a lower-resolution preview copy (proxy), generated in the background with progress shown on its media item; preview and timeline use it once ready (the original until then); export always uses the originals. Proxies are stored in a cache outside the project folder, reused across sessions and recreated if missing; the cache size is shown and a command clears it. "Preview quality" (REQ-051) replaces the on/off switch; with "Automatic" a source is big when it exceeds 1920x1080 pixels, or 1280x720 pixels on a machine with fewer than 8 logical cores or less than 8 GB of RAM. Acceptance: the decision is the same for the same resolution, cores and RAM; the exported file is identical whatever the Preview quality.
- REQ-039 (implemented): The application's memory use does not grow with the size of the source file. Acceptance: peak memory when importing and previewing a 4 GB source is at most the peak with a 100 MB source of the same resolution plus 200 MB.

## Key decisions
- When several jobs wait, the order is: preview first, then export, then import analysis, then background work (proxies, subtitle preparation). Proxy generation gives way and restarts later.
- The process limit applies to ffmpeg/ffprobe; speech recognition has its own limit. Both follow "How hard videolore works", and the limit is never below 3 because playback needs two processes.
- Proxies are never used for export. The proxy size rule is an assumption that gives the same answer on the same machine.
- Undoing back to the saved state counts as "no unsaved changes".
- Start and end fades belong to the edges of the video, not to the first or last clip, so "the video starts from black" stays true whatever is edited (1.2.0).
- Letterboxing colour is black. On macOS Cmd+Q goes through the unsaved-changes prompt (Ctrl+Q elsewhere).
- Default shortcuts follow common conventions; the full list is REQ-071 in [Window, menus and effects](business-ui.md).

### Project format history
Each format change makes older versions refuse the newer file with a message, leaving it untouched (REQ-029). Format numbers as in the code: 0.2.0 (new format, 0.1.x cannot open it); 1.2.0 (fades, clip volumes, subtitle positions); 1.2.6 (REQ-105); 1.3.0 (REQ-113); 1.4.0 (REQ-123); 1.5.0 (REQ-132); 1.6.0 (REQ-137 Apply LUT paths); 2.0.3 (REQ-158, REQ-159; a format 9 project saved by 2.0.3 becomes format 10, which 2.0.2 and older refuse); 2.0.4 (format 11); 2.1.0 (format 12); 2.2.0 (format 13); 2.3.0 (format 14, overlap media).

## Known limitations
- Removing a file from the media list also drops the undo history when an undo step refers to it.
- The proxy cache is never cleaned automatically; use "Clear preview copies" in Settings. After the proxies of a project are cleared, they are regenerated only after reopening the project or changing Preview quality.
- A 1280x720 source never gets a proxy under "Automatic" (the rule is "larger than").
- The memory acceptance test runs on a few minutes of video, not 4 GB (the 4 GB result is assumed from the design).
- On macOS the standard Hide and Minimize menu items are not available in this document's version (the 2.0.4 menu bar has them; see [Platforms and installers](business-platforms.md)).

## Out of scope
- Movable or floating panels: sections can be hidden, collapsed and docked left or right since 2.0.4 (see [Interface](business-interface.md)), but not moved freely.
